# 도담(dodam) 포팅 매뉴얼

> 아동 미술 심리 관찰·대화 AI 서비스 — 배포/이식을 위한 환경·절차 문서
> 대상 서버: `i15b209.p.ssafy.io` (AWS EC2, Ubuntu 24.04) · 도메인 HTTPS 적용
> 최종 갱신: 2026-07-26

## 1. 시스템 구성

단일 EC2에 Docker Compose 로 전 스택을 올린다. **외부에 열리는 포트는 80/443 뿐이며(nginx), 나머지 서비스는 모두 내부 네트워크 전용**이다. 아동 민감정보를 다루므로 DB·오브젝트 스토리지의 외부 노출면을 0으로 유지하는 것이 설계 원칙이다.

```
[사용자] ──443/80──> nginx (TLS 종단, 유일한 진입점)
                       ├── /api/      → backend  :8080   (Spring Boot)
                       ├── /ai/       → ai       :8000   (FastAPI)
                       ├── /jenkins/  → jenkins  :8080   (CI/CD)
                       ├── /grafana/  → grafana  :3000   (모니터링)
                       ├── /download/dodam.apk   (APK 배포)
                       └── /          → 정적 페이지(커뮤니티 웹 준비중)

내부 전용(호스트 포트 미개방): mysql:3306 · redis:6379 · minio:9000,9001
```

## 3. 환경변수 (값은 별도 제출 — 저장소에 없음)

`.env` 는 git 에 커밋하지 않는다. 배포 시에는 **Jenkins Credentials(Secret file, ID `dodam-env`)** 로 주입된다.

### 3-1. 필수 (미설정 시 배포가 즉시 실패 — `:?` fail-fast)

```
REDIS_PASSWORD          JWT_SECRET          AI_INTERNAL_TOKEN
```

### 3-2. 그 외 키 목록

| 분류 | 키 |
|------|-----|
| DB | `MYSQL_DATABASE`(=b209) `MYSQL_USER` `MYSQL_PASSWORD` `MYSQL_ROOT_PASSWORD` |
| 스토리지 | `STORAGE_MODE` `MINIO_ROOT_USER` `MINIO_ROOT_PASSWORD` `MINIO_BE_USER` `MINIO_BE_PASSWORD` `MINIO_AI_USER` `MINIO_AI_PASSWORD` |
| 인증 | `JWT_ISSUER` `JWT_ACCESS_TOKEN_TTL` `JWT_REFRESH_TOKEN_TTL` `KAKAO_APP_ID` `GOOGLE_CLIENT_ID` `OAUTH_CONNECT_TIMEOUT` `OAUTH_READ_TIMEOUT` |
| AI | `GMS_KEY` `GMS_BASE_URL` `LLM_MODEL` `STT_MODEL` `TTS_MODEL` `TTS_VOICE` `AI_BASE_URL` `AI_DRAWING_ANALYSIS_MODE` `AI_DRAWING_ANALYSIS_BASE_URL` `AI_IMAGE_ACCESS_BASE_URL` `AI_IMAGE_ACCESS_TOKEN_TTL` |
| 푸시 | `APP_PUSH_FCM_ENABLED`(기본 false) `FCM_CREDENTIALS_HOST_PATH` |
| 기타 | `SPRING_PROFILES_ACTIVE` `GRAFANA_ADMIN_PASSWORD` |

> `dodam-env` 크리덴셜은 **교체가 아니라 병합**이 규칙이다(기존 전체 키 + 신규 키를 합쳐 재업로드).
> 키를 빠뜨리면 Secrets Preflight 단계가 누락 목록을 출력하고 빌드를 중단시킨다.

### 3-3. 서버에 직접 두는 비밀 파일 (git·크리덴셜 아님)

| 경로 | 권한 | 용도 |
|------|------|------|
| `/etc/dodam/secrets/fcm-service-account.json` | `600 root:root` | FCM 푸시 Service Account 개인키 |

## 4. 빌드·배포 절차

### 4-1. 자동 배포 (표준) — Jenkins Multibranch Pipeline

`develop` 브랜치에 머지되면 자동 배포된다. 그 외 브랜치는 **빌드·테스트까지만** 수행한다.

```
Checkout
  → Compose Preflight     (전 브랜치) compose 의 리포지토리 상대경로 마운트 검출 시 실패
  → Secrets Preflight     (develop)   필수 키 누락·상대경로 값 검출 시 실패
  → Build & Test(backend) (전 브랜치) ./gradlew test bootJar
  → Docker Build          (develop)   backend·ai·nginx 이미지 빌드 + :<커밋SHA> 태그
  → Test — ai(import 스모크)
  → Deploy                (develop)   docker compose up -d
  → Healthcheck                       컨테이너 health + 게이트웨이 e2e 검증
  → Mattermost 알림
```

- 이미지는 레지스트리 없이 **같은 호스트에 로컬 빌드**(`:local`)하고, 롤백용으로 `:<커밋SHA>` 태그를 함께 남긴다.
- 트리거: Multibranch 브랜치 스캔(2분 주기 폴링). GitLab 웹훅 연동 시 즉시 트리거로 전환 가능.

### 4-2. 수동 배포 (서버에서)

```bash
cd ~/S15P11B209/infra
docker compose --env-file .env up -d          # 전체 기동
docker compose --env-file .env up -d backend  # 특정 서비스만
docker compose ps
```

### 4-3. 최초 구축 시 1회성 작업

```bash
# ① MinIO 버킷·계정·정책 프로비저닝 (멱등 — 재실행 안전)
docker compose --profile init build minio-init
docker compose --profile init run --rm minio-init

# ② TLS 인증서 최초 발급 (certbot 컨테이너, 이후 자동 갱신)
# ③ 비밀 파일 배치 (3-3 표 참조)
sudo mkdir -p /etc/dodam/secrets && sudo chmod 700 /etc/dodam
```

> DB 스키마는 backend 기동 시 **Flyway 가 자동 적용**한다(V1~V13). 수동 DDL 금지.

## 5. ⚠️ 배포 시 특이사항 (반드시 읽을 것)

### 5-1. compose 에 리포지토리 상대경로 마운트를 쓰지 않는다

Jenkins 는 **컨테이너 안에서 호스트 도커 데몬을 호출**한다(Docker-out-of-Docker). 이때 compose 의 상대경로(`./nginx`, `./secrets/...`)는 Jenkins 컨테이너 안 워크스페이스 기준으로 해석되지만 **실제 마운트는 호스트 데몬이 수행**하므로, 호스트에 없는 경로에는 도커가 **빈 디렉터리를 만들어 붙인다.** 설정·스크립트·비밀 파일이 조용히 사라진다.

실제 장애 2회: 2026-07-22 nginx 빈 conf · 2026-07-26 minio-init `exit 127`(서비스 전면 중단 2회).

**해법**
- 설정·스크립트 → **이미지에 bake** (빌드 컨텍스트는 tar 로 전송돼 실행 위치와 무관). nginx conf, minio init.sh 가 이 방식.
- 호스트 파일이 꼭 필요하면 → **워크스페이스 밖 절대경로** (`/etc/dodam/...`).
- 파이프라인의 **Compose/Secrets Preflight** 가 위반을 검출해 빌드를 실패시킨다.

### 5-2. 1회성 초기화는 배포 경로에서 분리한다

`minio-init` 은 `profiles: ["init"]` 으로 평상시 `up -d` 대상에서 제외돼 있고, `backend` 는 여기에 의존하지 않는다. 과거 `service_completed_successfully` 로 묶여 있어 프로비저닝 실패가 게이트웨이 중단으로 번진 사고가 있었다.

### 5-3. nginx conf 변경은 이미지 재빌드로만 반영된다

conf 는 bind 마운트가 아니라 이미지에 bake 되어 있다. conf 수정 → 커밋 → 파이프라인이 이미지를 재빌드하고 컨테이너를 재생성한다.

### 5-4. 배포 실패 시 스택이 부분 기동 상태로 남을 수 있다

`docker compose up -d` 가 중간에 실패하면 일부 컨테이너가 `Created` 상태로 남아 서비스가 중단된다. 이때는 `docker ps -a` 로 확인 후 해당 컨테이너를 기동하거나 재배포한다. 상세 절차는 `docs/인프라/배포검증-롤백.md`.

### 5-5. MySQL 8.4 데이터 디렉터리 업그레이드는 비가역

8.0 → 8.4 자동 업그레이드는 되돌릴 수 없다. 버전 변경 전 **반드시 mysqldump 백업**(`docs/인프라/DB백업-복원.md`).

## 8. 아동 민감정보 취급 원칙 (운영자 필독)

- DB·MinIO 의 내용은 **아동의 그림·음성·대화 원본**이다. 조회 자체가 민감정보 열람이며, 화면 밖으로 내보내지 않는다.
- 백업 파일은 암호화해 `/var/backups/dodam`(root 700)에 두고 서버 밖으로 복사하지 않는다.
- `ports:` 로 DB·스토리지를 외부에 여는 설정 추가 금지.
- 비밀 파일 사본은 최소로 유지한다(개인키는 `/etc/dodam/secrets` 한 벌).
