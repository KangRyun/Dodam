## 0. 한눈에 (TL;DR)

| 항목 | 값 |
|------|-----|
| 배포 방식 | 단일 EC2 + Docker Compose, 앱 계층(backend·ai·web) **블루-그린 무중단 배포** |
| 외부 개방 포트 | **80·443 뿐** (nginx). DB·스토리지·캐시는 내부 네트워크 전용 |
| CI/CD | Jenkins Multibranch — `develop` 머지 시 자동 빌드→푸시→블루-그린 배포 |
| 배포 스위치 | `DEPLOY_TARGET` (기본 `compose`, 부록 A 로 `k3s` 전환 가능) |
| 이미지 레지스트리 | 호스트 로컬 레지스트리 `127.0.0.1:5000`, 태그 = 커밋 SHA (라이브 = `0d62bd59`) |
| DB 스키마 | Flyway 자동 적용(backend 기동 시) — 수동 DDL 금지 |

```
                       ├── /api/        → backend    :8080  (Spring Boot)
                       ├── /ai/         → ai         :8000  (FastAPI)
                       ├── /jenkins/    → jenkins    :8080  (CI/CD)
                       ├── /grafana/    → grafana    :3000  (모니터링)
                       ├── /download/dodam.apk        (APK 배포)
                       ├── /legal/                    (약관·개인정보처리방침)
                       └── /            → web         :3000  (커뮤니티 웹)

내부 전용(호스트 포트 미개방): mysql:3306 · redis:6379 · mongodb:27017 · minio:9000
블루-그린: backend/ai/web 은 -blue / -green 두 정의가 있고 활성 색 1벌만 상시 기동.
           nginx 는 upstream-active.conf 의 *_active 를 참조 → 배포 시 스위치만 교체.
```

## 4. GitLab 클론 → 빌드 → 배포

### 4-1. 사전 준비 (서버)

```bash
# Docker + Compose v2, git 설치 전제 (Ubuntu 24.04)
git clone <GitLab 저장소 URL> S15P11B209 && cd S15P11B209

# 실행 환경파일 배치 (git 비추적 — §3 값으로 채운다)

cp infra/.env.active.example  infra/.env.active     # 최초엔 blue 로 시작
# 서버 비밀 파일 (§3-3)

sudo cp <fcm-key>.json /etc/dodam/secrets/fcm-service-account.json && sudo chmod 600 $_
```

### 4-3. 서버 최초 구축 (1회성 — 레거시→블루-그린 컷오버)

```bash
# ① 미들웨어(mysql·redis·mongodb·minio) + nginx 기동
docker compose -f infra/docker-compose.yml \
  --env-file infra/.env.compose --env-file infra/.env.active up -d \
  redis mysql mongodb minio nginx

# ② 활성 색(blue)으로 앱 3종 기동 (backend 기동 시 Flyway 가 스키마 자동 적용)
docker compose -f infra/docker-compose.yml \
  --env-file infra/.env.compose --env-file infra/.env.active up -d --no-deps \
  backend-blue ai-blue web-blue

# ③ healthy 확인 후 upstream 을 blue 로 전환 (bluegreen-deploy.sh 상단 런북 §0~4 참조)
docker exec dodam-nginx nginx -t && docker exec dodam-nginx nginx -s reload
```

> MinIO 버킷·계정·정책은 `infra/minio/`(`init.sh`·`policies/`·`lifecycle.json`) 로 프로비저닝.
> TLS 최초 발급 후 갱신은 호스트 crontab certbot(`infra/cron/dodam-certbot-renew.sh`).
> DB 스키마는 backend 기동 시 **Flyway 가 자동 적용** — 수동 DDL 금지. (제출 덤프는 `exec/db/` 참조)

### 4-4. 자동 배포 (표준) — Jenkins Multibranch

`develop` 브랜치 머지 시 자동 배포. 그 외 브랜치는 **빌드·테스트까지만**.

```
Checkout
  → Compose/Secrets Preflight  (상대경로 마운트·필수키 누락 검출 시 실패)
  → Build & Test (backend)     ./gradlew test bootJar
  → Docker Build               backend·ai·web·nginx 이미지 + :<커밋SHA> 태그
  → Test — ai (import 스모크)
  → Deploy (develop)           DEPLOY_TARGET=compose → bluegreen-deploy.sh 로 유휴 색 배포·스위치
  → Healthcheck                게이트웨이 e2e 검증
  → Mattermost 알림
```

- 이미지는 로컬 레지스트리 `127.0.0.1:5000` 에 `:<커밋SHA>` 로 푸시(불변 복원지점).
- `DEPLOY_TARGET` = 빌드 파라미터 > `/var/jenkins_home/DEPLOY_TARGET` 파일 > 기본 `compose`.

### 4-5. 수동 배포 (서버에서 블루-그린)

```bash
# 서비스 하나를 새 태그로 유휴 색에 띄우고 → healthy 대기 → nginx 스위치 → 옛 색 정지

infra/scripts/bluegreen-deploy.sh ai      <이미지태그>
infra/scripts/bluegreen-deploy.sh web     <이미지태그>

# 롤백 (직전 색·태그로 복귀)
infra/scripts/bluegreen-deploy.sh --rollback backend

# 현재 활성 색·태그 확인
cat infra/.env.active        # ACTIVE_* / IMAGE_TAG_*_*
docker ps --format '{{.Names}}\t{{.Status}}'
```

> 상태의 단일 출처 = `infra/.env.active`. `upstream-active.conf` 는 여기서 파생되니 **손으로 고치지 말 것**.

## 5. ⚠️ 배포 시 특이사항 (요구사항 1-③, 반드시 읽을 것)

### 5-1. compose 에 리포지토리 상대경로 마운트를 쓰지 않는다
Jenkins 는 컨테이너 안에서 **호스트 도커 데몬을 호출**(DooD)한다. compose 의 상대경로(`./nginx`)는 Jenkins 워크스페이스 기준으로 해석되지만 실제 마운트는 호스트 데몬이 수행 → 호스트에 없는 경로엔 **빈 디렉터리가 붙어** 설정·비밀이 조용히 사라진다. (실장애 2회: 2026-07-22 nginx 빈 conf · 2026-07-26 minio-init `exit 127`)
**해법:** 설정·스크립트는 **이미지에 bake**(nginx conf, minio init.sh), 호스트 파일이 꼭 필요하면 **절대경로**(`/etc/dodam/...`, `PVC_ROOT`). 파이프라인 Preflight 가 위반을 검출해 실패시킨다.

### 5-2. nginx conf 변경은 이미지 재빌드로만 반영된다
운영 conf 는 bind 가 아니라 이미지에 bake(`infra/nginx/conf.d`). 단, **블루-그린 활성 색 스위치**(`conf.d.compose/upstream-active.conf`)만은 `bluegreen-deploy.sh` 가 다시 쓰고 `nginx -s reload` 한다. conf 로직 변경 → 커밋 → 파이프라인 재빌드.

### 5-3. 블루-그린은 "상시 이중화"가 아니라 "무중단 배포"다
노드 RAM 15G·가용 8.2G 제약으로 **활성 색 1벌만 상시 기동**한다. 유휴 색은 배포 순간에만 뜬다. 단일 노드라 HA(SPOF 제거)는 애초 목표가 아니다.

### 5-4. `docker compose up -d` (전체/`--remove-orphans`) 를 함부로 돌리지 말 것
전체 up 은 활성 색이 아닌 색까지 건드리거나 orphan 제거로 라우팅을 깰 수 있다. 앱 배포는 반드시 `bluegreen-deploy.sh` 로만.

### 5-5. AI 그림분석 타임아웃은 90s 로 늘려 둔 상태다
성공 케이스 평균 17.6s·최대 34s + YOLO 콜드스타트가 겹치면 기본 30s 를 넘긴다. 넘기면 `error_code` 가 `INVALID_RESPONSE` 로 찍혀 원인이 통신 타임아웃임을 가린다. `AI_DRAWING_ANALYSIS_READ_TIMEOUT=90s` 유지.

### 5-6. MySQL 8.4 데이터 디렉터리 업그레이드는 비가역
8.0 → 8.4 자동 업그레이드는 되돌릴 수 없다. 버전 변경 전 **반드시 mysqldump 백업**(`docs/인프라/DB백업-복원.md`).

### 5-7. 데이터는 k3s local-path PVC 경로를 bind 로 재사용한다
컷백 시 데이터 무이동 원칙 — `PVC_ROOT=/var/lib/rancher/k3s/storage` 아래를 그대로 bind. `root:root 700` 이라 일반 사용자는 못 읽지만 도커 데몬(root)이 마운트하므로 동작에는 문제없다.

## 부록 B. 아동 민감정보 취급 원칙 (운영자 필독 — 가드레일 9절)

- DB·MinIO·Mongo 의 내용은 **아동의 그림·음성·대화 원본**이다. 조회 자체가 민감정보 열람이며 화면 밖으로 내보내지 않는다.
- **제출 DB 덤프(`exec/db/`)에는 아동 데이터를 넣지 않는다** — 구조 + 코드성 마스터만.
- 백업 파일은 암호화(AES-256)해 서버 안(root 700)에만 둔다.
- `ports:` 로 DB·스토리지를 외부에 여는 설정 추가 금지(외부 개방은 80/443 뿐).
- 비밀 파일 사본은 최소로(개인키는 `/etc/dodam/secrets` 한 벌).
- AI 리포트는 진단이 아니다 — 모든 리포트에 한계 고지 유지. 해석 문장에는 근거·확신도 부착.
