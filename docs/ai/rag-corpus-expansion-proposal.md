# RAG 코퍼스 확장 제안 — "전문가 역할을 AI가 대신할 때 필요한 근거"

- 상태: **제안(초안)** — 이 문서는 코퍼스를 바꾸지 않는다. 무엇이 더 필요한지만 적는다.
- 작성: 2026-08-05 · 소유: AI 파트
- 상위 정본: `docs/ai/rag-corpus-policy.md` (§1 원칙 · §2 라이선스 · §3 용도 태그 · §5 보관 · §6 매니페스트)
- 관문(그대로 유효): 자체 저작 코퍼스는 **프롬프트 자산과 동급으로 검토**한다 — 운영 인덱스 배포 전
  편주희(프롬프트·안전)·상담사 자문 교차 확인(정책 §4b). 이 제안이 그 관문을 건너뛰지 않는다.

> ⚠️ 이 문서는 **코퍼스 파일을 새로 쓰거나 교체하지 않는다.** `ai/rag/corpus/`·`corpus-manifest.json`은
> 손대지 않았다. 실제 집필·채택은 위 관문을 통과한 뒤 별도 이슈에서 한다.

---

## 1. 왜 지금 제안하는가

2026-08-05에 리포트의 독자 구조가 바뀌었다. "사람 전문가가 초안을 검토한다"는 전제가
**실측으로 부정됐고**(`ObservationReviewStatus` 값이 `AI_DRAFT` 하나뿐 · 다른 상태로 가는 전이 코드
0건 · `report/` 패키지에 EXPERT 읽기 경로 0건 · 운영 `report_observed_features` 97건 전량
`EXPERT_ONLY`), 그 자리를 **AI 자체검토(2-pass)** 가 대신하기로 했다.

바뀐 것은 관문만이 아니다. **근거의 무게가 달라졌다.**

| | 전(가정) | 후(실제) |
|---|---|---|
| 해석의 최종 책임 | 사람 전문가가 읽고 거른다(고 믿었다) | 아무도 안 읽었다 → 이제 AI 자체검토 |
| RAG 근거의 역할 | 관찰 어휘 보조 | **해석을 지탱하는 유일한 외부 지식** |
| 근거가 얇을 때 | 전문가가 메운다(고 믿었다) | 메울 사람이 없다 |

즉 RAG 코퍼스는 이제 "있으면 좋은 어휘집"이 아니라 **AI가 사람 없이 판단할 때 기대는 유일한 외부 지식**이다.

## 2. 현 코퍼스 실태

`ai/rag/corpus/dodam-observation-guide-v1.txt` — 자체 저작, **8청크**(문단 단위 분할, 평균 385자.
`rag.chunking.split`으로 실측). 내용을 훑으면 **전부 '보호자에게 건네는 일반 발달 안내'** 다:

- 비언어 표현이 아이 마음의 창이다 / 3~5세 반복 그림은 자연스럽다 / 저학년은 이야기를 붙인다
- 같은 나이라도 표현 차이가 크다 / 감정에 이름 붙이기 / "모르겠어"도 감정 표현이다
- 복합 감정은 흔하다 / 열린 질문이 좋다 / 평가 대신 관찰을 말해 주기
- 건너뛰기 존중 / 과정에 관심 갖기 / 그리기는 놀이다 / 작업 스타일은 다양하다
- 한 번으로 판단하지 않기 / 다른 아이와 비교하지 않기

**보호자 교육 자료로는 잘 쓰였다.** 하지만 "AI가 전문가 역할을 대신한다"는 새 전제에서 보면 세 가지가 비어 있다.

| 구멍 | 지금 코퍼스로는 | 결과 |
|---|---|---|
| **① 관찰 → 서술 어휘** | "표현 차이가 크다"까지만. 무엇을 어떤 말로 적을지가 없다 | 해석 문장이 매번 새로 지어진다 — 근거가 아니라 문체가 결과를 정한다 |
| **② 정상 범위(base rate)** | "한 번으로 판단하지 말라"는 태도 지침만 | AI가 "흔한 일"과 "눈여겨볼 일"을 가를 기준이 없다 → 과대해석·과소해석 양쪽으로 흔들린다 |
| **③ 상담 권유 판단 근거** | 마지막 문단에 "여러 활동에 걸쳐 반복되면 상담" 한 줄 | `expertReviewRequired`(사람 상담 권유)를 켤 기준이 사실상 없다 — 지금은 모델 감(感)에 맡겨져 있다 |

**②가 가장 큰 구멍이다.** 자체검토(`report_review.txt`)가 `OVERREACH`를 잡으려면 "이 정도는 흔한 일"을
알아야 하는데, 그 지식이 코퍼스에 없어 지금은 검토자도 생성자와 같은 사전지식에 기댄다.
같은 모델이 같은 사전지식으로 스스로를 검토하면 **공통 오류는 잡히지 않는다.**

## 3. 추가로 필요한 코퍼스의 성격 (제안)

정책 §3의 용도 태그를 그대로 쓰되, 아래 세 갈래를 **우선순위 순으로** 채우자고 제안한다.
전부 §1 원칙(아동 데이터 금지·비진단·재배포 허용 라이선스·출처 유지)을 그대로 지킨다.

### 제안 A ─ 연령대별 '흔한 표현' 기준선 (태그: `DEV_STAGE`, 신규 보조 태그 `BASE_RATE` 검토)

- **내용:** 만 3~5세 / 초등 저학년 / 초등 고학년 각 구간에서 **흔하게 나타나는** 그림 표현과
  활동 행동. "크게 그린다·작게 그린다", "한두 색만 쓴다", "여러 번 지운다", "빨리 끝낸다"가
  각 연령에서 얼마나 평범한 일인지를 **서술문으로** 적는다.
- **왜 필요한가:** 자체검토의 `OVERREACH` 판정에 실질적 기준을 준다. 지금은 "흔한 일"인지
  판단할 근거가 없어, 평범한 표현에 의미를 붙이는 문장을 검토자가 통과시킬 수 있다.
- **⚠️ 넣지 말 것:** 수치 규준·백분위·연령별 점수표. 그건 정책 §1-2가 배제하는 '해석 기준표'이고,
  점수화 금지(07/17 방향 전환)에 정면으로 걸린다. **"흔하다/드물지 않다" 수준의 서술만.**
- **형태 제안:** 연령 구간마다 3~5문단. 각 문단은 한 가지 표현 축(크기 / 색 / 수정 / 속도 / 구성).

### 제안 B ─ 관찰 서술 어휘집 (태그: `EMOTION_VOCAB`, `ART_ACTIVITY`)

- **내용:** 같은 관찰을 **낙인 없이 적는 여러 표현**의 대조 목록을 산문으로.
  "여러 번 고쳐 그렸다"를 적는 말들 / "한 가지 색만 썼다"를 적는 말들 /
  "빨리 끝냈다"를 적는 말들 — 각각에 대해 **관찰 문장 / 조심스러운 해석 문장 / 쓰면 안 되는 문장**.
- **왜 필요한가:** `report_common`의 사실·해석 분리 원칙은 "나눠 담아라"까지만 말하고
  **어떤 말로** 담을지는 모델 재량이다. 어휘가 코퍼스에 있으면 회차 간 표현 흔들림이 줄고,
  `STIGMA` 판정 기준도 문서화된 어휘에 붙는다.
- **⚠️ 넣지 말 것:** 부위별 상징 의미(문=개방성 등). 정책 §1-2b가 "상징의 뜻 자체는 문장에 적지 않는다"로
  못 박았다. 어휘집은 **표현 방식**의 목록이지 **의미**의 목록이 아니다.

### 제안 C ─ 상담 권유가 필요한 상황의 서술 (태그: `PARENT_TALK`, 신규 보조 태그 `REFERRAL` 검토)

- **내용:** "어떤 상황에서 사람 전문가와 이야기해 보길 권하는가"를 **비진단 서술**로.
  단발 관찰이 아니라 **반복·지속·일상 변화 동반**이라는 조건 중심으로.
  더불어 "권유가 곧 문제 확인이 아니다"라는 전달 태도.
- **왜 필요한가:** `expertReviewRequired`가 2026-08-05에 **'사람 상담을 권할 신호'** 로 재정의됐다.
  이건 이제 AI가 사람에게 넘기는 **유일한 축**인데, 켤 기준이 문서 어디에도 없다.
  기준이 없으면 두 방향으로 다 틀린다 — 아무 때도 안 켜지거나, 무거운 단어만 보면 켜진다.
- **⚠️ 넣지 말 것:** 위기 개입 절차·자해/학대 대응 지침. 그 경로는 `crisis_detection`·`crisis_guidance`가
  **규칙 기반으로** 소유한다. LLM 근거로 섞으면 위기 대응이 확률적 판단이 된다.
  ⚠️ 이 제안 C는 "상담 권유"만 다룬다. 위기 대응은 여전히 사람·규칙의 몫이다.

### 우선순위

1. **A (기준선)** — 자체검토의 실효를 좌우한다. 없으면 2-pass가 자기 사전지식을 재확인하는 데 그친다.
2. **C (상담 권유)** — 사람에게 넘기는 유일한 축이라, 비어 있으면 안전망이 작동을 안 한다.
3. **B (어휘)** — 품질·일관성 개선. 안전 축은 아니다.

### 라이선스 경로

정책 §4에서 외부 후보 1차가 **전원 탈락**했고(권리 불명·NC·제4유형), 그래서 §4b로 자체 저작 트랙을 열었다.
A·B·C 모두 **자체 저작 트랙**을 전제로 제안한다 — 라이선스 위험 0이고, 서비스 톤·비진단 방침에 맞춘다.
외부 공공누리 1유형 산문 재조사는 §4 방침대로 계속하되, **그것을 기다리며 코퍼스를 비워 두지 않는다.**

## 4. 그림일기에도 RAG를 실을 것인가 — 의견

**현황:** `report_client.generate()`는 HTP에서만 RAG를 검색한다. 그림일기는 `RAG_NOT_APPLICABLE`로
표시하고 건너뛴다. 근거는 모듈 주석에 있다 — "전문 자료 인용이 필요한 쪽은 '검사처럼 읽히기 쉬운'
HTP 리포트다. 가벼운 그림일기는 활동 데이터만으로 담백하게."

**의견: 방향은 바꿔야 하지만, 지금 바꾸면 안 된다.**

바꿔야 하는 이유:

- 이 결정의 전제가 "HTP만 위험하다"였다. 그런데 위험한 것은 활동 유형이 아니라 **근거 없는 해석**이고,
  그건 그림일기에서도 똑같이 난다. 오히려 그림일기는 주제가 자유로워 관찰 재료가 흔들리고,
  자동 탐지도 자주 놓친다(`report_diary` 1.5.0이 "블록에 없는 것이 그림에 없다고 단정하지 마"를 넣은 이유).
  **근거가 얇은 쪽에 근거를 안 주고 있다.**
- 사람 전문가가 있다고 믿던 시절에는 "가벼운 리포트는 담백하게"가 성립했다. 이제 두 활동 모두
  최종 관문이 AI 자체검토다. 한쪽만 지식 없이 판단하게 두는 근거가 사라졌다.

지금 바꾸면 안 되는 이유:

- 코퍼스가 **아직 §3의 A·B·C를 못 갖췄다.** 현 코퍼스(보호자 일반 안내)를 그림일기에도 실으면
  근거는 안 늘고 프롬프트 길이와 임베딩 비용만 는다. **RAG를 켜는 것이 아니라 코퍼스를 채우는 것이 먼저다.**
- `report_diary.txt`의 근거 화이트리스트에 `[전문 자료 근거]`가 없다. 검색만 켜고 프롬프트를 안 고치면
  모델이 그 블록을 통째로 버린다 — 구 `report.txt`에서 실제로 났던 사고다(모듈 주석 §49~54).
  화이트리스트·평가 케이스(`expects_rag`)·회귀 테스트가 함께 움직여야 한다.

**제안하는 순서:** ① 코퍼스 A·B·C 집필 → ② 관문 통과(편주희·상담사) → ③ `report_diary` 화이트리스트에
`[전문 자료 근거]` 추가 + `_search_rag` 분기 제거 → ④ 평가 케이스 `expects_rag` 갱신.
③ 이전에 검색만 켜는 것은 **비용만 늘고 근거는 안 느는 변경**이라 하지 않는다.

## 5. 이 제안이 건드리지 않은 것

- `ai/rag/corpus/dodam-observation-guide-v1.txt` — 그대로. 관문(정책 §4b) 없이 손대지 않는다.
- `ai/rag/corpus-manifest.json` · `knowledgeBaseVersion` — 그대로(`kb-2026.07-1`).
- `report_client._search_rag`의 HTP 전용 분기 — 그대로(위 §4의 순서 ③ 전까지).
- 정책 §1 원칙·§2 라이선스 기준 — 이 제안은 그 안에서만 움직인다.

## 6. 후속 확인 필요 (판단을 남겨 둔 것)

- 신규 보조 태그(`BASE_RATE`·`REFERRAL`)를 정책 §3 표에 추가할지, 기존 태그로 흡수할지 — 정책 소유자 판단.
- 제안 A의 "흔하다" 서술이 사실상 규준표로 읽힐 위험 — **상담사 자문이 반드시 필요한 지점**이다.
  경계가 애매하면 A를 좁혀서(연령별 '자연스러운 표현'의 예시 나열까지) 시작하는 편이 안전하다.
- 코퍼스가 두꺼워지면 `RAG_TOP_K`(현재 5)·`RAG_SCORE_THRESHOLD`(현재 0.35) 재조정 필요 —
  청크가 늘면 임계값 통과가 쉬워져 관련 없는 근거가 붙는다.
