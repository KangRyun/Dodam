## 1. 데이터 유형별 저장소 매핑 (확정)

| 데이터 | 저장소 | 근거 |
|---|---|---|
| 그림 원본 | **MinIO** `dodam/images/` | 파일을 DB에 넣으면 버퍼캐시 오염·백업 비대·HTTP 스트리밍 불가. 파일은 조인·트랜잭션이 필요 없다 — DB엔 key(메타)만 |
| 아동 음성 녹음 | **MinIO** `dodam/audio/` | 동일. 기존 stage(로컬 검증)→promote(업로드) 2단계 유지 |
| TTS 캐시 | **MinIO** `dodam/tts-cache/` | 재생성 가능한 파생물 → **백업 제외** 프리픽스 |
| PDF 리포트 | **MinIO** `dodam/reports/` | `reports.pdf_storage_key` 컬럼 기존재 |
| 동의 증빙 | **MinIO** `dodam/evidences/` | 법적 보존 — **TTL·자동삭제 구조적 제외**, 백업 필수 |
| 스트로크(그리기 과정) | **MongoDB** `strokes` | 좌표=행이면 행마다 인덱스 갱신·redo 비용. 조인 없이 "세션 단위 통째 재생"만 하는 append-only → 배치=문서 임베딩이 I/O 수십 분의 1 |
| 대화 로그 원문 | **MongoDB** `conversation_events` | append-only 고볼륨 + 스키마 유연 + **TTL 인덱스로 보관기간 가드레일 구현** |
| 관계형 핵심 (사용자·아동·동의·세션/분석 메타) | **MySQL** 유지 | FK 무결성·트랜잭션이 필요한 "관계" 데이터 |
| 캐시·토큰 | **Redis** 유지 | 변경 없음 |
| 업로드 임시(stage) | 로컬(k8s emptyDir) | 검증용 1회성 — 영속 불필요 |

**원칙 한 줄:** 파일은 오브젝트 스토리지, 관계는 MySQL, 고볼륨 로그는 MongoDB, DB에는 언제나 key/메타만.

## 2. MinIO 설계

| 항목 | 결정 | reason |
|---|---|---|
| 배포 | k8s StatefulSet 1replica + PVC 20Gi (k3s local-path) | 컷오버 후 처음부터 k8s로 — compose 이중 설치 낭비 금지 |
| 버전 | 릴리스 태그 고정 (latest 금지) | 재현성. ⚠️ 2025년 이후 커뮤니티 릴리스는 웹 콘솔 대부분 제거 — **콘솔 의존 금지, mc CLI 운영** |
| 리소스 | requests 256Mi/250m · limits 1Gi/1CPU | 공용 15GB 서버 보호 (limits 없는 파드 금지) |
| 버킷 | **단일 버킷 `dodam` + 프리픽스 5종** | 버킷 분리는 단일 테넌트에서 정책 관리만 늘림. IAM·ILM·삭제큐 매핑 모두 프리픽스 스코프로 충분 |
| 접근 | ClusterIP 전용 · 콘솔(9001) 미노출 · **버킷 익명 정책 없음(default deny) 명시 유지** | 외부 노출면 80/443 유지(가드레일). 관리는 port-forward |
| 자격증명 | 3벌: `root`(프로비저닝 전용) / `dodam-be-rw`(버킷 rw) / `dodam-ai-ro`(**images/ GetObject만**) | 최소권한 — AI 키는 목록·삭제 불가 |
| at-rest 암호화 | **EBS 볼륨 암호화(인프라 레벨) 1순위** — SSAFY/AWS 콘솔에서 확인 필요(OS 내부에서 판별 불가, 369 선행 체크) | MinIO SSE는 KES 별도 배포 필요 — 단일노드에서 과투자. 앱측 암호화는 4차 후보 |
| 백업 | `mc mirror` CronJob (353 mysql-backup.sh의 보관·취급 규정 패턴 재사용) · tts-cache 제외 | site replication은 서버 2대 필요 — 불가. 단일노드에서 유일한 현실 수단 |

메모리 예산: 현행 ~9GB + MinIO 1Gi + Mongo 1.5Gi ≈ **11.5 / 15GB** (여유 3.5GB — 초과 시 모니터링 스택 우선 축소)

## 3. 파일 서빙 = 백엔드 프록시 스트리밍 (presigned URL 탈락 — 확정)

- **presigned URL 탈락 사유**: "URL 소지 = 접근"인 bearer 토큰. 아동 그림 URL이 히스토리·로그·공유로 새면 만료 전까지 누구나 열람 → **보호자-아동 관계·전문가 열람 범위의 요청별 인가가 우회**된다(가드레일 9절). MinIO 외부 노출도 필요해 80/443 원칙까지 깨짐.
- **프록시 방식**: 매 요청 JWT + 관계 검증 → `StreamingResponseBody`로 스트리밍(메모리 버퍼링 금지) + `Cache-Control: private, no-store`. 소규모 트래픽에서 BE 경유 비용은 무시 가능.
- BE 통합: `ImageStorage`/`AudioStorage`에 **read(storageKey) 추가** + AWS SDK v2 S3 구현체(`endpointOverride`+`forcePathStyle` — 코드 그대로 진짜 S3 이전 가능), `app.storage.mode=local|s3` 스위치(로컬 구현 보존 = 즉시 롤백 수단). 기존 파일은 `mc cp` 이관 — key 구조 동일이라 **DB 변경 0**.

## 5. MongoDB 문서 설계 (364·365 구체화)

```js
// strokes 컬렉션 — 배치 1건 = 문서 1개 (포인트=문서 금지: 수십 KB ≪ 16MB 제한)
{ sessionId, childId, batchSeq,
  strokes: [{ strokeSeq, tool, color, points: [[x, y, elapsedMs, pressure], ...] }],
  pointCount, createdAt, expireAt }
// 인덱스: {sessionId:1, batchSeq:1} unique · {childId:1}(탈퇴 동반삭제) · expireAt TTL
```

- **인증·접근 제어 (safety-review R-368 반영)**: Mongo도 MinIO와 동일 원칙 — **auth 필수**(`root` 관리 계정 + `dodam-app` 앱 계정 분리, 앱 계정은 해당 DB만), ClusterIP 전용, 시크릿은 sync-secrets 편입 + 필수키 게이트. 백업은 364의 mongodump CronJob(353 취급 규정 동일).
- **TTL = 보관기간 가드레일 구현**: `expireAt = createdAt + 보관정책`. 동의 철회·탈퇴는 TTL을 기다리지 않고 `deleteMany({childId})` **즉시 실행**. 보관정책이 바뀌면 기존 문서의 `expireAt` 소급 갱신 여부를 함께 결정(→ §9 열린 질문).
- **as-built 경과 (2026-08-02 정정 · 671)**: 위 문단들이 전제한 "스트로크 BE 코드 미구현"은 07/23
  시점 사실이다. 그 뒤 순서가 이렇게 흘렀다 — ① 스트로크가 MySQL JPA(좌표=1행)로 먼저 구현·운영
  진입 → ② **365 에서 MongoDB 전환 완료**: 현재 쓰기 경로는 `StrokeBatchService` →
  `StrokeBatchDocument`(배치=문서)다. 계약 규칙(순번 unique·checksum 멱등·내용 다른 재사용 409·
  이벤트 500개·1 MiB)은 전환 후에도 유지된다(`storage-contract-alignment.md` §5).
  ③ 기존 MySQL 데이터는 **옵트인 일회성 러너**(`STROKE_MONGO_BACKFILL=true` →
  `StrokeMongoBackfillRunner`)로 이관한다 — 즉 "스키마 제거"가 아니라 **이관 + 병행 잔존**이 실체다.
  MySQL `stroke_*` 테이블·엔티티는 아직 남아 있으며, 제거(Flyway)는 이관 완료 실증 후 별도 결정.
- `conversation_events`: **365 는 스트로크만 전환하고 종결됐다.** 대화 원문의 단일 소스는 여전히
  MySQL(`conversation_messages`)이다 — Mongo 전환 여부는 미결로 남는다. **확정 전 이중 저장 금지** 원칙 유지.
- **as-built 정정 (2026-08-06 · S15P11B209-973)**: 위 문단과 initdb 주석은 이 컬렉션을 "대화 로그 **원문**"이라
  부르지만, 실제로 채워지기 시작한 것은 **행동 이벤트**다. 973 이 적재를 붙이면서 범위를 이렇게 갈랐다.
  - **넣는 것**: 질문 제시·음성 답변·칩 답변·건너뛰기·대화 종료의 발생 시각, 응답 지연(질문 제시→행동),
    답변 수단, 고른 칩 **개수**, 직접 입력 **유무**, 녹음 길이·종료 사유, 종료 사유·질문 수.
  - **넣지 않는 것**: 질문·답변 **본문**, STT 전사, 직접 입력 내용, 고른 칩의 라벨·코드. 즉 "무엇을 했는가"만
    남기고 "무슨 말을 했는가"는 남기지 않는다 (CLAUDE.md 9절).
  - 따라서 **이중 저장 금지 원칙은 깨지지 않는다** — 원문의 단일 소스는 여전히 MySQL 이고, Mongo 에는 원문이 없다.
    원문 전환 여부는 여전히 미결이며, 결정 시 이 컬렉션에 원문을 얹을지 별도 컬렉션을 둘지 함께 정할 것.
  - 문서 필드·의미는 `ConversationEventDocument` javadoc 이 정본이다. 인덱스 키(`sessionId`·`seq`·
    `childId`·`expireAt`)는 initdb 가 만든 것을 그대로 쓰며 앱은 인덱스를 만들지 않는다.
  - `seq` 는 **세션 내 순번이 아니라 전역 단조 증가**다. 세션별 카운터 문서가 무한히 늘어나는 것을 피한 선택이며,
    한 세션만 뽑아 `seq` 오름차순으로 정렬하면 발생 순서가 그대로 나온다. 번호가 비는 것은 정상이다.
  - 적재는 **best-effort + 커밋 이후**다. 아이가 쓰는 화면이라 관측 로그 실패가 대화를 끊으면 안 된다 — 실패는
    WARN 로그만 남고 소비자가 결측을 견뎌야 한다. **이벤트 수를 정합성 근거로 쓰지 말 것.**
  - TTL 은 `app.conversation-event.retention-days`(기본 180일)로 `expireAt` 을 계산해 넣고, 동의 철회·탈퇴·
    활동 삭제는 TTL 을 기다리지 않고 `deleteMany` 로 즉시 지운다(스트로크와 같은 규칙).

## 8. 가드레일 자체 점검 (9절 대응)

- 외부 노출면 80/443 불변 (MinIO·Mongo 전부 ClusterIP) ✅

- 최소권한 (ai-ro = images GetObject만) ✅
- 보관기간·탈퇴 삭제 (TTL + deleteMany + 삭제 큐 워커) ✅
- at-rest 암호화 — **EBS 암호화 콘솔 확인 필요** (369 선행 체크) ⚠️
- 증빙(evidences/)은 자동삭제 구조적 제외 ✅
- 파일 열람 감사 로그(누가 어떤 아동 그림을 언제 봤나 — audit_logs 연동)는 **4차 후보**로 기록 ⏭

## 9. 열린 질문 (팀·자문 결정 필요 — safety-review 확인필요 2건)

1. **탈퇴 시 evidences/ 처리**: 동의 증빙은 법적 보존 대상인데 탈퇴 시 아동 데이터는 삭제 원칙 — 보존 기간·비식별화 방식을 심리상담 자문/팀과 결정 (분쟁 대비 보존 vs 삭제권의 충돌)
2. **보관정책 변경의 소급 적용**: 정책이 30일→14일로 바뀌면 기존 데이터의 expireAt도 당기는가 — 동의 버전 관리와 연동해 결정
