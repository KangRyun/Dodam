| 대화 로그 원문 | **MongoDB** `conversation_events` | append-only 고볼륨 + 스키마 유연 + **TTL 인덱스로 보관기간 가드레일 구현** |

| 업로드 임시(stage) | 로컬(k8s emptyDir) | 검증용 1회성 — 영속 불필요 |

**원칙 한 줄:** 파일은 오브젝트 스토리지, 관계는 MySQL, 고볼륨 로그는 MongoDB, DB에는 언제나 key/메타만.

## 2. MinIO 설계

| 항목 | 결정 | reason |
|---|---|---|
| 배포 | k8s StatefulSet 1replica + PVC 20Gi (k3s local-path) | 컷오버 후 처음부터 k8s로 — compose 이중 설치 낭비 금지 |
| 버전 | 릴리스 태그 고정 (latest 금지) | 재현성. ⚠️ 2025년 이후 커뮤니티 릴리스는 웹 콘솔 대부분 제거 — **콘솔 의존 금지, mc CLI 운영** |
| 리소스 | requests 256Mi/250m · limits 1Gi/1CPU | 공용 15GB 서버 보호 (limits 없는 파드 금지) |
| 버킷 | **단일 버킷 `dodam` + 프리픽스 5종** | 버킷 분리는 단일 테넌트에서 정책 관리만 늘림. IAM·ILM·삭제큐 매핑 모두 프리픽스 스코프로 충분 |
| 접근 | ClusterIP 전용 · 콘솔(9001) 미노출 · **버킷 익명 정책 없음(default deny) 명시 유지** | 외부 노출면 80/443 유지(가드레일). 관리는 port-forward |
| 자격증명 | 3벌: `root`(프로비저닝 전용) / `dodam-be-rw`(버킷 rw) / `dodam-ai-ro`(**images/ GetObject만**) | 최소권한 — AI 키는 목록·삭제 불가 |
| at-rest 암호화 | **EBS 볼륨 암호화(인프라 레벨) 1순위** — SSAFY/AWS 콘솔에서 확인 필요(OS 내부에서 판별 불가, 369 선행 체크) | MinIO SSE는 KES 별도 배포 필요 — 단일노드에서 과투자. 앱측 암호화는 4차 후보 |
| 백업 | `mc mirror` CronJob (353 mysql-backup.sh의 보관·취급 규정 패턴 재사용) · tts-cache 제외 | site replication은 서버 2대 필요 — 불가. 단일노드에서 유일한 현실 수단 |

메모리 예산: 현행 ~9GB + MinIO 1Gi + Mongo 1.5Gi ≈ **11.5 / 15GB** (여유 3.5GB — 초과 시 모니터링 스택 우선 축소)

## 3. 파일 서빙 = 백엔드 프록시 스트리밍 (presigned URL 탈락 — 확정)

- **presigned URL 탈락 사유**: "URL 소지 = 접근"인 bearer 토큰. 아동 그림 URL이 히스토리·로그·공유로 새면 만료 전까지 누구나 열람 → **보호자-아동 관계·전문가 열람 범위의 요청별 인가가 우회**된다(가드레일 9절). MinIO 외부 노출도 필요해 80/443 원칙까지 깨짐.
- **프록시 방식**: 매 요청 JWT + 관계 검증 → `StreamingResponseBody`로 스트리밍(메모리 버퍼링 금지) + `Cache-Control: private, no-store`. 소규모 트래픽에서 BE 경유 비용은 무시 가능.
- BE 통합: `ImageStorage`/`AudioStorage`에 **read(storageKey) 추가** + AWS SDK v2 S3 구현체(`endpointOverride`+`forcePathStyle` — 코드 그대로 진짜 S3 이전 가능), `app.storage.mode=local|s3` 스위치(로컬 구현 보존 = 즉시 롤백 수단). 기존 파일은 `mc cp` 이관 — key 구조 동일이라 **DB 변경 0**.

## 4. AI 이미지 접근 = ai-ro 직접 GET (확정)

| 옵션 | 판정 |
|---|---|
| ① AI가 `dodam-ai-ro`로 MinIO 직접 GET | **채택** — 내부망 통신, 최소권한, 계약의 storageKey 의미 그대로 |
| ② BE가 bytes 내부 전송 | 탈락 — 계약 재작업 + 메모리 2회 복사 |
| ③ presigned URL 전달 | 탈락 — 계약 "URL 변환 금지" 조항 위반 + 유출 리스크 |

부수: 계약 부록(storageKey 해석 규칙 = 버킷 `dodam`, key 원문), AI 이미지 바이트 로그 금지 재확인.

## 5. MongoDB 문서 설계 (364·365 구체화)

```js
// strokes 컬렉션 — 배치 1건 = 문서 1개 (포인트=문서 금지: 수십 KB ≪ 16MB 제한)
{ sessionId, childId, batchSeq,
  strokes: [{ strokeSeq, tool, color, points: [[x, y, elapsedMs, pressure], ...] }],
  pointCount, createdAt, expireAt }
// 인덱스: {sessionId:1, batchSeq:1} unique · {childId:1}(탈퇴 동반삭제) · expireAt TTL
```

- **인증·접근 제어 (safety-review R-368 반영)**: Mongo도 MinIO와 동일 원칙 — **auth 필수**(`root` 관리 계정 + `dodam-app` 앱 계정 분리, 앱 계정은 해당 DB만), ClusterIP 전용, 시크릿은 sync-secrets 편입 + 필수키 게이트. 백업은 364의 mongodump CronJob(353 취급 규정 동일).
- **TTL = 보관기간 가드레일 구현**: `expireAt = createdAt + 보관정책`. 동의 철회·탈퇴는 TTL을 기다리지 않고 `deleteMany({childId})` **즉시 실행**. 보관정책이 바뀌면 기존 문서의 `expireAt` 소급 갱신 여부를 함께 결정(→ §9 열린 질문).
- MySQL `stroke_batches`·`stroke_events`·`stroke_event_points`: 코드 미구현 → 데이터 이관이 아니라 **스키마 v1.3 개정에서 제거** + ERD spec 갱신.
- `conversation_events`: 대화 원문의 단일 소스를 Mongo로 할지 MySQL `conversation_messages` 유지할지는 **365에서 BE와 협의 확정** (audio_variants FK 제약 고려). **확정 전 이중 저장 금지.**
