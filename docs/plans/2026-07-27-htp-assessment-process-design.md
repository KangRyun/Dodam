## 1. 왜 이 기획이 필요한가

우리 앱의 그림 활동은 **그림 1장 = 세션 1개**로 설계돼 있다(`drawing_sessions`, 명세 §10.1). 반면 HTP 검사는 **집·나무·남자 사람·여자 사람 4장을 정해진 순서로 그리는 한 묶음**이 검사 1회다. 즉 지금 구조로는 HTP를 "그림 활동 4번"으로밖에 표현할 수 없고, 4장을 하나의 검사로 묶어 순서를 보장하고 종합 결과를 내는 개념이 없다.

`DrawingCategory.ASSESSMENT` Enum은 이미 명세 §4에 있으나(§10.3에서 "검사형 코드를 지원하더라도…"로 언급), 검사형 활동 코드도 진행 절차도 정의된 바 없다. 이 문서가 그 절차를 정한다.

## 2. 논문에서 무엇을 가져오고 무엇을 버리는가

### 2.1 채택

| 논문 요소 | 채택 이유 |
| --- | --- |
| 4장 고정 순서 (집 → 나무 → 남자 사람 → 여자 사람) | HTP 표준 실시 순서. 순서 자체가 해석 근거가 된다 |
| 이전 그림 미완료 시 다음 그림 비활성 | 논문 4-2절. 순서 일탈로 인한 검사 신뢰도 저하 방지 |
| 검사 전 안내 화면 3종 (준비 / 종이 방식 / 그림판 방식) | 논문 그림 17·18·20. "평가가 아니다"를 먼저 고지해 아동 긴장 완화 |
| 종이 검사 시 용지 방향 지침 | 논문 4-2절. 집=가로, 나무·사람=세로. 촬영 방향이 어긋나면 위치·비율 해석이 무의미 |
| 그림 도구 제한 (검정 펜 + 지우개) | 논문 4-2절. HTP는 연필·흰 종이가 표준. 색상 자유도가 검사 표준화를 깬다 |
| 소요 시간 기록 | 논문 4-2절. 우리는 이미 `drawingDurationMs`로 수집 중이며 **step별로 따로** 잰다(논문은 4장 합계 1쌍만 잰다) |
| 정량 척도 항목 (크기 비율·용지 내 배치·필수 요소 유무·부위 비율) | 논문 3-3절이 인용한 박희진(2011) 「HTP 평가기준 개발: 리커트 척도화」 기반. **단, 전문가용 자료로만 노출** |
| 낮은 temperature(0.15)로 해석 일관성 확보 | 논문 표 4. 우리 VLM 프롬프트에도 동일 원칙 적용 |
| 개별 결과 + 종합 결과 분리 제공 | 논문 그림 22. 4장을 각각 보고 나서 묶어 보는 구조 |

| 웹(React) 전제의 `react-signature-canvas` | 우리 클라이언트는 Flutter. 기존 캔버스 구현 재사용 |

### 2.3 논문에 없지만 우리가 추가하는 것

- **AI 대화 (PDI 대응)** — 임상 HTP의 사후질문(Post-Drawing Interview)을 우리 AI 대화 기능으로 수행. 논문은 그림만 분석하고 아동 발화를 전혀 쓰지 않는다(논문 4-2절 프로세스 4단계에 아동 질의응답이 없다). 우리는 아이의 실제 말을 리포트 1급 재료로 쓴다(§13.4 `representativeUtterances`). **그림 1장을 그릴 때마다 그 자리에서 진행한다** — 위치 근거는 §3.4.
- **탐지 기반 품질 게이트** — 해당 주제가 탐지되지 않으면 다시 그릴 기회를 준다. 논문에는 없는 단계.
- **행동 데이터** — pause·undo·erase·도구 변경·필압. 우리는 이미 `stroke-batches`로 수집 중이며 논문보다 풍부하다.

## 3. 검사 진행 순서 (확정 제안)

### 3.1 전체 흐름

```
[준비]  활동 선택 → 검사 안내 → 방식 선택 → 방식별 지침
   ↓
[step1 집]        그리기 → 제출·탐지 → 탐지 확인 → 대화(2문항)
   ↓
[step2 나무]      그리기 → 제출·탐지 → 탐지 확인 → 대화(2문항)
   ↓
[step3 남자 사람] 그리기 → 제출·탐지 → 탐지 확인 → 대화(2문항)
   ↓
[step4 여자 사람] 그리기 → 제출·탐지 → 탐지 확인 → 대화(2문항)
   ↓
[마무리] 감정 선택(1회) → 종합 분석 → 결과 화면 → (선택) 전문가 공유
```

한 step은 **그리기와 대화를 함께** 끝낸다. step N의 대화가 끝나야 step N+1 그리기가 열린다.

### 3.2 준비 단계

| 순서 | 화면 | 내용 | 비고 |
| --- | --- | --- | --- |
| 1 | 활동 선택 | 보호자가 활동 목록에서 `HTP` 검사를 선택 | 기존 `GET /drawing-types`에 `category=ASSESSMENT` 항목으로 노출 |
| 2 | 검사 안내 | 평가가 아님 고지 / 예상 소요 20~30분 / **그림 4장을 순서대로 그리고, 한 장 그릴 때마다 그 그림에 대해 이야기를 나눈다**(전체 순서 예고) / 보호자 역할 = 순서 안내만, 그림 내용에 개입 금지 | 논문 그림 17 대응 |
| 3 | 방식 선택 | `종이 그림 검사` / `그림판 검사` | 기존 `inputMethod` = `UPLOAD` / `CANVAS` 재사용 |
| 4-A | 종이 방식 지침 | 준비물(A4 4장, 연필·지우개) / 용지 방향(집=가로, 나무·사람=세로) / 촬영 요령(그림자·기울기 없이 정면) / **한 장씩 그리고 바로 촬영해 올린다** | 논문 그림 18 대응. 논문의 4장 일괄 첨부(그림 19)는 쓰지 않는다 |
| 4-B | 그림판 방식 지침 | 검정 펜·지우개만 사용 / 순서 안내 / 그림판 조작 방법 | 논문 그림 20 대응 |

**보호자 안내 문구는 "잘 그리는 것을 평가하지 않는다"를 반드시 포함한다.** 논문이 아동 긴장 완화를 명시적 설계 목표로 삼은 부분이고, 우리 §2.4 신뢰성 원칙과도 맞는다.

### 3.3 step 진행 (4회 반복)

각 step은 아래 4개를 끝내야 다음 step이 열린다.

| 순서 | 단계 | 처리 | 재사용 API |
| --- | --- | --- | --- |
| 5 | 그리기 | 캔버스 작성 또는 종이 촬영. 주제 안내 문구 표시("집을 그려볼까요?") | `PUT /draft`, `POST /stroke-batches`, `POST /upload` |
| 6 | 제출 | FINAL asset 저장 + 객체 탐지 동기 실행 | `POST /drawing-complete` (DRAWING-09) |
| 7 | 탐지 확인 | 해당 주제의 whole 박스가 잡혔는지 검사 | `htp_labels.summarize().subjects_drawn` |
| 8 | 대화 | 방금 그린 그림의 탐지 결과를 근거로 질문 2개 | `POST /conversations`, `POST /questions` (§3.4) |

**step별 주제와 기대 탐지값**

| step | 주제 | 안내 문구 | 기대 `subjects_drawn` | 용지 방향(종이) |
| --- | --- | --- | --- | --- |
| 1 | 집 | "집을 그려볼까요?" | `HOUSE` | 가로 |
| 2 | 나무 | "이번엔 나무를 그려볼까요?" | `TREE` | 세로 |
| 3 | 남자 사람 | "남자 사람을 한 명 그려볼까요?" | `PERSON` | 세로 |
| 4 | 여자 사람 | "여자 사람을 한 명 그려볼까요?" | `PERSON` | 세로 |

step3·4는 탐지 라벨이 동일하다(`PERSON`). 성별 구분은 **아동에게 준 지시**로만 기록하며, AI가 그림에서 성별을 판정하지 않는다 — 근거 없는 추정을 만들지 않는다는 원칙(`analysis_service.py` 설계 원칙)에 따른다.

### 3.4 대화 (step 안, 그림 직후)

그림 제출·탐지가 끝나면 **그 자리에서** 해당 그림에 대해 대화한다. 화면에는 방금 그린 그림이 그대로 떠 있다.

| 항목 | 값 |
| --- | --- |
| 시점 | step N 탐지 확정 직후, step N+1 그리기 전 |
| 질문 수 | 2개 (검사 전체 8개) |
| 근거 | 그 step의 `OBJECT_DETECTION` 분석 (`basisAnalysisId`) |
| API | `POST /drawing-sessions/{stepSessionId}/conversations` (`maxQuestionCount=2`) → `POST /questions` |
| 답변 | 음성·선택형 (기존 계약 그대로) |

기존 대화 계약은 세션 1개에 묶여 있고 `basisAnalysisId`로 근거 분석을 지정한다. step 세션이 곧 그림 1장이므로 **계약을 그대로 쓴다.** 세션은 `DRAWING → ANALYZING → CONVERSING → REFLECTION`을 순서대로 타며, 우회나 대기 상태가 없다.

#### 왜 4장을 다 그린 뒤가 아니라 그림마다 바로 대화하는가

**아동 발화 품질이 결정적 이유다.** 아이는 방금 그린 그림을 가장 잘 설명한다. 4장을 다 그린 뒤로 미루면 첫 그림에 대한 기억이 20분 이상 지난 상태라 "몰라요"·"그냥요"가 늘고, 8문항을 몰아 답해야 해 뒤로 갈수록 답이 짧아진다. 우리 리포트는 아이 발화를 1급 재료로 쓰므로(§13.4 `representativeUtterances`) 이 손실이 곧 결과 품질 손실이다.

**부수 이점:** 그리기와 대화가 번갈아 나오면 연속 4장 그리기의 지루함이 끊긴다. 구현 면에서도 기존 세션 상태 흐름을 그대로 타므로 검사 묶음에 별도 phase가 필요 없다(§4.1).

**포기하는 것 — 검사 오염 가능성.** 집에 대해 대화한 직후 나무를 그리면 그 대화가 다음 그림에 영향을 줄 수 있다. HTP는 4장을 같은 심리 상태의 산물로 묶어 해석하는 검사이므로 이 위험은 실재한다. 다음으로 완화한다:

- 질문을 **그린 것에 대한 사실 확인·묘사 유도**로 한정한다(누가 사는 집인지, 나무가 어디 있는지). 심리 해석·평가·제안을 하지 않는다.
- **다음 주제를 언급하지 않는다.** 집 대화에서 나무·사람을 꺼내지 않는다(질문 생성 프롬프트 제약으로 강제).
- 대화 종료 후 곧바로 다음 그림 안내로 넘어가 대화가 여운을 남기지 않게 한다.
- 대화 시각과 다음 그림 시작 시각을 기록해, 종합 분석에서 개입 간격을 확인할 수 있게 한다.

임상 PDI도 그림 직후 질문이 표준이며, 논문이 배치 구조를 쓴 것은 아동 발화를 아예 수집하지 않기 때문이다(논문 4-2절에 질의응답 단계가 없다). 발화를 쓰는 우리 설계에는 논문 구조가 그대로 적용되지 않는다.

#### 대화 규칙

- 그림별 질문 수는 2개(검사 전체 8개). 일반 활동 기본값 10개를 4번 반복하면 아동 피로가 과도하다.
- 아이가 답하기 싫어하면 그림별로 건너뛸 수 있다(기존 §12.8 건너뛰기 재사용). 건너뛴 그림은 대화 없이 다음 step으로 넘어간다.
- 4개 step 대화를 모두 건너뛰어도 검사는 완료할 수 있다. 이때 종합 분석 입력에서 대화가 빠지고 `unusedInputs`에 그 사실을 남긴다.

### 3.5 마무리 단계

| 순서 | 단계 | 처리 |
| --- | --- | --- |
| 9 | 감정 선택 | 검사 전체에 대해 1회. 아이가 감정 복수 선택 + 직접 표현(선택) |
| 10 | 종합 분석 | 4장의 탐지·시각·행동·대화를 묶어 AI 서버에 종합 분석 요청 |
| 11 | 결과 화면(보호자) | 4장 썸네일 / 무엇을 그렸는지 / 아이가 한 말 / 활동 기록(시간·멈춤·지우기) / 보호자 대화 가이드 / 한계 고지 |
| 12 | 전문가 공유(선택) | 동의 시 정량 지표·AI 관찰 초안까지 전문가에게 공개 |

**감정 선택을 그림별이 아니라 검사 끝에 1회로 두는 이유**
기존 그림 활동은 세션마다 `REFLECTION` 단계에서 감정·제목을 받는다. HTP에 그대로 적용하면 4번 반복돼 아동 피로가 크고, 임상 HTP도 그림마다 감정 라벨을 받지 않는다. 따라서 step 세션 4개의 `REFLECTION`은 모두 `skipped=true`로 통과시키고, 검사 단위 감정 선택을 1회 받는다. 그림 제목도 검사에서는 받지 않는다(자유 활동과 달리 주제가 지정돼 있어 제목이 의미를 갖지 않는다).

## 4. 상태 모델

### 4.1 구조 — 검사 묶음이 기존 세션 4개를 소유

```
htp_assessment (신규)
 ├─ status: IN_PROGRESS | COMPLETED | EXPIRED | ABANDONED | DELETED
 ├─ currentStep: 1..4   (진행 중인 step. 그리기·대화 모두 이 step 안에서 일어난다)
 ├─ inputMethod: CANVAS | UPLOAD  (검사 중 변경 불가)
 ├─ expiresAt
 └─ steps[4] → drawing_session (기존 엔티티 그대로)
        step1 HOUSE / step2 TREE / step3 PERSON_MALE / step4 PERSON_FEMALE
```

**검사 묶음에 별도 `phase`를 두지 않는다.** 그리기와 대화가 한 step 안에 있으므로 "지금 그리는 중인지 대화 중인지"는 **해당 step 세션의 `currentStage`가 이미 표현한다**(`DRAWING`/`ANALYZING`/`CONVERSING`/`REFLECTION`). 검사 묶음은 "몇 번째 step인지"(`currentStep`)와 "검사 전체가 끝났는지"(`status`)만 알면 된다. 마무리 단계(감정·종합 분석)는 `currentStep=4` 세션이 `COMPLETED`가 된 이후 구간으로 판별한다.

### 4.2 검사와 step 세션 상태의 관계

```
검사 IN_PROGRESS, currentStep=1
  step1 세션: DRAWING → ANALYZING → CONVERSING → REFLECTION(skipped) → COMPLETED
      ↓ currentStep=2
  step2 세션: DRAWING → ANALYZING → CONVERSING → REFLECTION(skipped) → COMPLETED
      ↓ currentStep=3
  step3 세션: DRAWING → ANALYZING → CONVERSING → REFLECTION(skipped) → COMPLETED
      ↓ currentStep=4
  step4 세션: DRAWING → ANALYZING → CONVERSING → REFLECTION(skipped) → COMPLETED
      ↓ 4장 완료
  검사 단위 감정 선택 → 4장 종합 분석 + 리포트 생성
      ↓
검사 COMPLETED
```

**기존 세션 계약을 그대로 탄다.** `POST /drawing-complete`(DRAWING-09)가 탐지 확정 후 `currentStage=CONVERSING`으로 바꾸면 곧바로 대화가 열리고, 대화가 끝나면 `REFLECTION`을 `skipped=true`로 통과시켜 세션을 `COMPLETED`로 닫는다. 대기 상태나 상태 우회가 없으므로 DRAWING-09를 포함해 세션 계약 수정이 필요 없다.

이 구조를 택한 이유: 그림 저장·탐지·대화·행동 수집·리포트가 이미 세션 단위로 완성돼 있다. 묶음 관리만 얇게 위에 올리면 기존 자산 전부를 재사용할 수 있고, 검사형이 아닌 일반 활동에는 영향이 없다.

### 4.3 순서 강제 규칙

- step N 세션이 `COMPLETED`(그리기·탐지·대화·REFLECTION 통과)에 도달하기 전에는 step N+1 세션을 생성하지 않는다(위반 시 `409`).
- 대화는 해당 step 세션이 `CONVERSING`일 때만 시작할 수 있다. 탐지 확정 전 대화 요청은 `409`.
- 이미 완료한 step은 다시 그릴 수 없다(재작성은 §4.5 탐지 실패 재유도 경로에서만 허용).

#### 기존 세션 중복 규칙과의 관계 — 예외 불필요

명세 §10.4는 "같은 아동에게 복구 가능한 `IN_PROGRESS` 세션이 있으면 `409 ACTIVE_DRAWING_SESSION_EXISTS`"를 규정한다. 이 흐름에서는 **step N 세션이 `COMPLETED`가 된 뒤에야 step N+1 세션이 생성되므로 동시에 열린 `IN_PROGRESS` 세션이 항상 1개**다. 기존 규칙과 충돌하지 않고, 예외 처리도 필요 없다.

> 이전 개정(4장 일괄 그리기)에서는 step 세션 4개가 동시에 `IN_PROGRESS`로 열려 §10.4 예외가 필수였다. 그림마다 대화하는 지금 구조에서는 그 예외 요구가 사라진다 — §6.2에서도 철회했다.

부수 효과로, 검사 진행 중 같은 아동의 일반 그림 활동은 여전히 차단된다(진행 중인 step 세션이 `IN_PROGRESS`이므로). 이건 의도한 동작이다.

### 4.4 중단·재개·만료

| 상황 | 처리 |
| --- | --- |
| 그리는 중 중단 | 검사 `IN_PROGRESS`, `currentStep=N` 유지. 재진입 시 step N 그리기부터 이어간다(기존 draft 복구 재사용) |
| 대화 중 중단 | 검사 `IN_PROGRESS`, `currentStep=N` 유지. step N 세션이 `CONVERSING`이므로 재진입 시 그 그림을 다시 보여주고 남은 질문부터 이어간다 |
| 4장 완료 후 마무리 전 중단 | 검사 `IN_PROGRESS`, step 세션 4개 모두 `COMPLETED`. 재진입 시 감정 선택부터 |
| 유효기간 초과 | **7일** 경과 시 `EXPIRED`. 이미 그린 그림은 보존하되 종합 분석은 만들지 않는다 |
| 보호자가 검사 포기 | `ABANDONED`. 그린 그림은 개별 활동 기록으로 남긴다 |

유효기간 7일은 **4장이 모두 완료되기 전까지**에 적용한다. 4장이 다 모인 뒤(감정·종합 분석 구간)의 재개는 그림이 이미 확정됐으므로 기간 제약을 걸지 않는다.

**7일 유효기간을 두는 이유:** HTP는 한 시점의 심리 상태를 보는 검사다. 며칠 간격으로 그린 4장을 하나로 묶어 해석하면 근거가 없다. 다만 아동이 한 번에 4장을 못 그리는 것은 정상이므로 하루 안 완료를 강제하지는 않는다.

### 4.5 탐지 실패 시 재유도 (순서 7)

step1인데 `HOUSE` whole 박스가 안 잡힌 경우:

1. "집이 잘 안 보여요. 다시 그려볼까요?" 안내 + `[다시 그리기]` / `[이대로 진행]` 선택
2. `[다시 그리기]`: 같은 step에서 새 FINAL asset을 만든다. 재시도 **최대 2회**
3. `[이대로 진행]`: 그대로 대화 단계로 넘기고 검사 결과에 `limitations`로 "집 그림에서 집을 확인하지 못했습니다"를 남긴다

탐지에 실패한 그림도 대화는 진행한다. 모델이 못 잡은 그림일수록 아이 설명이 유일한 단서다. 다만 질문 생성 근거가 빈약하므로 일반형 질문("무엇을 그렸는지 이야기해줄래?")으로 대체한다.

**강제로 막지 않는 이유:** 아동이 집을 그렸는데 모델이 못 잡는 경우(추상적 표현, 저품질 촬영)와 아동이 실제로 다른 것을 그린 경우를 서버가 구분할 수 없다. 진행을 막으면 전자에서 검사가 영구 중단된다. 못 찾았다는 사실을 숨기지 않고 남기는 쪽이 안전하다 — `unusedInputs`/`warnings` 원칙과 동일.

## 5. 종합 분석 정책

### 5.1 입력

4개 step의 데이터를 묶어 AI 서버에 전달한다.

| 입력 | 출처 | 현재 상태 |
| --- | --- | --- |
| 그림 4장 + 탐지 결과 | 각 step의 FINAL asset, `OBJECT_DETECTION` 분석 | 구현됨 |
| 시각 특징 (잉크 밀도·밝기·채도·점유율) | `analysis_service._visual_features` | 구현됨 |
| 행동 특징 (시간·pause·undo·erase) | `stroke-batches` 집계, step별 | 구현됨 |
| 대화 (질문·아동 답변) | 각 step 세션 대화, 전체 8문항 내외 | 구현됨 |
| 검사 단위 감정 선택 | 마무리 단계 | 신규 |
| 정량 척도 (크기 비율·배치·부위 비율) | 탐지 bbox에서 계산 | **신규 계산 필요** |

### 5.2 정량 척도 산출 (논문 3-3절 기반)

탐지 bbox는 이미 0~1 정규화돼 있어(`bbox_norm_xywh`) 추가 모델 없이 계산 가능하다.

| 항목 | 계산 | 대상 |
| --- | --- | --- |
| 크기 비율 | whole 박스 면적 / 용지 면적 | 집·나무·사람 |
| 용지 내 배치 | whole 박스 중심 좌표의 9분할 위치 | 집·나무·사람 |
| 필수 요소 유무 | `HOUSE_ROOF`/`HOUSE_WALL`/`HOUSE_WINDOW`/`HOUSE_DOOR` 탐지 여부 | 집 |
| 부위 비율 | `TREE_ROOT`:`TREE_TRUNK`:`TREE_CROWN` 높이 비 | 나무 |
| 부위 비율 | `PERSON_HEAD`:`PERSON_UPPER_BODY`:`PERSON_LEG` 높이 비 | 사람 |
| 부위 누락 | 눈·입·손·발 등 탐지 여부 | 사람 |

**이 수치는 계산해서 저장하되, 논문처럼 점수로 환산해 심리적 의미를 붙이지 않는다.** 리커트 척도로 점수화하는 순간 진단형 산출물이 되고, 그건 우리 §13.4가 금지한다. 수치는 전문가가 판단 근거로 쓰는 raw feature로만 제공한다.

### 5.3 결과 공개 범위

| 대상 | 제공 | 금지 |
| --- | --- | --- |
| 보호자 | 4장 썸네일, 무엇을 그렸는지(탐지 객체명), 아이가 한 말, 활동 기록(시간·멈춤·지우기 횟수), 보호자 대화 가이드, 한계 고지 | AI 추정 감정·확률, 리커트 점수, 관찰 초안, RAG 해석 |
| 전문가(공유 동의 시) | 위 전부 + 정량 척도, 시각·행동 특징, AI 관찰 초안(`AI_DRAFT`), 불확실성, `unusedInputs` | — |

기존 리포트 2계층(`ParentActivityReport` / `ExpertReviewMaterial`, §13.1)을 그대로 쓴다. HTP 전용 리포트 타입을 새로 만들지 않고, 검사 단위 리포트가 4개 세션을 참조하도록 확장한다.

## 7. 미결정 사항과 제안 기본값

| # | 결정 사항 | 제안 기본값 | 근거 |
| --- | --- | --- | --- |
| 1 | 4장 전부 vs 3장 축소(집·나무·사람) | **4장** | 논문·임상 표준. 아동 피로가 실측으로 문제되면 그때 축소 검토 |
| 2 | 검사 유효기간 | **7일**(4장 완료 전까지 적용) | 한 시점 심리 상태 가정을 유지하는 최소 제약 |

| 4 | 감정 선택 위치 | **검사 종료 시 1회** | 그림별 4회는 아동 피로 + 임상 HTP에 없는 절차 |

| 6 | 탐지 실패 시 재시도 횟수 | **2회** | 무한 재시도는 아동 부담, 0회는 저품질 촬영에서 검사 손실 |
| 7 | 정량 척도 계산 위치 | **AI 서버(`ai/`)** | bbox·이미지 크기를 이미 다루는 곳. BE에 두면 탐지 결과를 다시 해석하는 중복이 생김 |

| 9 | 진행 중 일반 활동 차단 | **차단** | 진행 중 step 세션이 `IN_PROGRESS`이므로 기존 규칙으로 충족. 예외 처리 불필요(§4.3) |
| 10 | 대화 위치 | **그림 1장마다 바로** (2026-07-27 확정) | 그린 직후 발화 품질이 가장 높다. 오염 위험은 질문 범위 제한으로 완화 — 근거는 §3.4 |
| 11 | 대화 건너뛰기 허용 | **허용**(그림별·전체 모두) | 아이가 말하기 싫어하는 상황에서 검사 자체를 못 끝내게 만들면 안 된다. 대화 없이도 그림·행동 데이터로 종합 분석은 가능하며 `unusedInputs`에 사실을 남긴다 |
| 12 | 오염 완화 강도 | **질문 범위 제한 + 다음 주제 언급 금지**(§3.4) | 대화를 그림 직후로 두는 대가. 프롬프트 제약으로 강제하고 실측 후 조정 |
