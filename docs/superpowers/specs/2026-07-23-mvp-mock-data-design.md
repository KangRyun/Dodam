# S15P11B209-136 MVP 테스트용 Mock 데이터 설계

## 목적

로컬 개발자가 운영 데이터나 실제 OAuth 자격 증명 없이 주요 화면과 API 개발에 사용할 수 있는 일관된 MVP 데이터 세트를 제공한다. Mock 데이터는 명시적으로 활성화한 `local` Profile에서만 주입하며, 운영 환경과 자동화 테스트의 데이터 생명주기에는 관여하지 않는다.

## 범위

다음 데이터를 하나의 연관된 시나리오로 구성한다.

- 보호자 역할의 사용자와 소셜 인증 계정
- 보호자가 조회할 수 있는 아동과 보호자·아동 관계
- 그림 활동 생성에 사용할 활성 그림 유형
- 진행 중 활동 조회·재개에 사용할 대표 그림 활동

다음 항목은 구현하지 않는다.

- OAuth 또는 JWT 인증 우회
- 실제 Provider Access Token, Refresh Token 또는 Secret
- 운영 Profile 데이터 초기화
- 실제 AI 서버 호출이나 성공 결과 임의 생성
- 물리 파일에 의존하는 그림 자산, 완료 활동, 분석, 대화 및 리포트
- 기존 Flyway Migration 변경
- 물리 이미지·음성 파일을 가장하는 불완전한 저장소 데이터

## 초기화 방식

`local` Profile 전용 초기화 컴포넌트가 별도 SQL 리소스를 실행한다. 컴포넌트는 `APP_MOCK_DATA_ENABLED=true`에 대응하는 애플리케이션 설정이 활성화된 경우에만 생성한다.

SQL은 MySQL 8.x 문법을 사용하며, Mock 데이터 전용 고정 식별자와 고유 키를 기준으로 재실행 가능하게 작성한다. 동일한 Seed를 여러 번 실행해도 중복 Row가 쌓이지 않아야 한다. 기존 사용자가 만든 데이터는 수정하거나 삭제하지 않는다.

Flyway의 버전 Migration에는 Seed를 넣지 않는다. 이를 통해 운영 배포 시 Mock 데이터가 자동 적용되는 경로를 원천적으로 분리한다.

## 구성 요소

### Mock 데이터 설정

`application-local.yml`에 Mock 데이터 활성화 속성을 추가한다. 기본값은 비활성화하며, 로컬 개발자가 환경 변수로 명시적으로 켜도록 한다.

### 초기화 컴포넌트

초기화 컴포넌트는 다음 조건을 모두 만족할 때만 동작한다.

- 활성 Profile이 `local`이다.
- Mock 데이터 활성화 속성이 `true`이다.
- DataSource와 Flyway Migration 적용이 완료되어 있다.

SQL 실행 중 오류가 발생하면 애플리케이션 시작을 실패시킨다. 일부 데이터만 적용된 상태를 정상 시작으로 숨기지 않으며, 오류 메시지에 Secret, 전체 SQL, DB 제약조건 이름을 노출하는 별도 로그를 작성하지 않는다.

### Seed SQL

Seed SQL은 외래 키 의존 순서에 맞춰 부모 Row부터 삽입한다. 테이블별 필수 컬럼, Enum 문자열, 길이 및 Check Constraint는 최신 Flyway Schema와 일치시킨다.

물리 파일이 필요한 자산은 생성하지 않는다. 저장소에 실제 파일이 없는데도 다운로드 가능한 것처럼 보이는 `storage_key`를 추가하지 않으며, 이에 의존하는 완료 시나리오는 Seed 대상에서 제외한다.

## 데이터 시나리오

기본 Seed는 다음 개발 흐름을 지원한다.

1. 보호자 사용자와 소셜 계정의 DB 연관 관계 확인
2. 보호자 기준 아동 상세 조회
3. 활성 그림 유형 조회 및 새 그림 활동 생성
4. 진행 중 그림 활동 조회·재개

인증은 기존 OAuth 로그인과 Access Token 검증을 그대로 사용한다. Seed 계정만으로 외부 Provider 인증을 통과할 수 있다고 문서화하지 않는다.

## 오류 처리

- 설정이 비활성화되어 있으면 초기화 컴포넌트가 생성되지 않는다.
- Schema와 SQL이 불일치하면 시작 실패로 즉시 드러낸다.
- 재실행 시 고유 키 충돌을 정상적인 멱등 처리로 흡수한다.
- Mock 데이터가 아닌 기존 Row를 삭제하거나 덮어쓰지 않는다.

## 테스트

다음 항목을 자동 검증한다.

- `local` Profile이 아니면 초기화 컴포넌트가 활성화되지 않는다.
- 활성화 속성이 없거나 `false`이면 초기화되지 않는다.
- 활성화 속성이 `true`이면 Seed SQL 실행 경로가 선택된다.
- Seed SQL을 MySQL Testcontainers에 연속 두 번 실행해도 중복 또는 제약조건 오류가 발생하지 않는다.
- 사용자, 소셜 계정, 아동, 보호자 관계, 그림 유형 및 진행 중 활동의 외래 키 관계와 Enum 값이 예상대로 저장된다.

Docker를 사용할 수 없어 Testcontainers 검증을 실행하지 못하면 테스트를 삭제하거나 우회하지 않고 미실행 사유를 완료 보고에 남긴다.

## 문서화

README에는 다음 내용만 추가한다.

- `local` Profile에서 Mock 데이터를 활성화하는 환경 변수
- 데이터가 개발 편의를 위한 값이며 실제 OAuth 인증을 우회하지 않는다는 제한
- 운영 환경에서 활성화하지 않아야 한다는 주의사항

실제 Secret, 사용자 PC 절대 경로, 유효 Token은 기록하지 않는다.

## 완료 조건

- Mock 데이터가 `local` Profile과 명시적 활성화 속성으로 격리된다.
- 동일 SQL을 반복 실행할 수 있다.
- 기존 Migration과 운영 데이터가 변경되지 않는다.
- 최신 Schema의 제약조건과 Enum 문자열을 만족한다.
- 관련 테스트와 전체 Gradle 검증이 성공한다.
