# 캔버스 색상 선택 확정 흐름

## 목적

팔레트의 HSV 조절 과정에서 발생하는 모든 중간 색상이 최근 사용 색상에 저장되는 문제를 없앤다. 사용자가 `선택`으로 확정한 색상만 캔버스 도구와 최근 사용 색상에 반영한다.

## 상호작용 계약

- 팔레트를 열면 현재 도구 색상을 `기존 색상`과 `임시 색상`의 초깃값으로 사용한다.
- HSV 면, 색조 막대, 채널 슬라이더를 조절하면 `임시 색상`과 팔레트 미리보기만 갱신한다.
- 최근 사용 색상을 누르면 해당 색상을 `임시 색상`으로 미리보기만 한다.
- `선택`을 누르면 임시 색상을 현재 도구 색상으로 적용하고 최근 사용 색상 맨 앞에 한 번 추가한 뒤 팔레트를 닫는다.
- `닫기`, 태블릿 바깥 영역 탭, 모바일 바텀시트 dismiss는 변경을 취소한다.
- 취소 시 도구 아이콘 포인트 색상과 캔버스 커서 색상도 기존 값을 유지한다.

## 상태와 데이터 흐름

1. 캔버스 화면이 팔레트를 열 때 현재 색상을 스냅샷으로 보관한다.
2. 팔레트는 독립적인 임시 HSV 상태를 소유한다.
3. 팔레트의 `onChanged`는 임시 상태만 변경한다.
4. `선택`은 확정 색상을 결과값으로 반환한다.
5. 캔버스 화면은 결과값이 있을 때만 기존 `_setColor` 경로를 호출한다.
6. 결과값이 없으면 아무 상태도 변경하지 않는다.

최근 사용 색상의 중복 제거, 최신순 정렬, 최대 10개 제한은 기존 `_setColor` 계약을 그대로 사용한다.

## 컴포넌트 변경

### `DrawingColorPalette`

- `선택`과 `닫기` 액션을 노출한다.
- HSV 조절과 최근 색상 탭은 임시 선택 콜백만 발생시킨다.
- 버튼은 모바일과 태블릿에서 동일한 레이블과 순서를 사용한다.

### 캔버스 화면

- 태블릿 팝오버와 모바일 바텀시트가 확정 색상을 반환하도록 연결한다.
- 확정 결과에만 `_setColor`를 호출한다.
- 외부 dismiss를 취소 결과로 취급한다.

## 접근성

- 버튼 레이블은 각각 `닫기`, `선택`으로 제공한다.
- `선택`은 현재 미리보기 색상을 확정하는 버튼임을 semantics에서 알 수 있게 한다.
- 기존 HSV 키보드 조작과 최근 색상 semantics는 유지한다.

## 테스트

- HSV를 여러 번 조절해도 캔버스 색상과 최근 색상이 즉시 변경되지 않는다.
- 최근 색상을 눌러도 미리보기만 변경된다.
- `선택` 시 최종 색상 하나만 적용되고 최근 색상 맨 앞에 추가된다.
- 같은 색상을 확정하면 중복 없이 맨 앞으로 이동한다.
- 최근 색상은 최대 10개를 유지한다.
- `닫기`, 외부 탭, 모바일 dismiss 시 기존 색상을 유지한다.
- 모바일 바텀시트와 태블릿 팝오버가 같은 계약을 따른다.

## 범위 제외

- 팔레트의 HSV 시각 디자인 변경
- 빠른 색상 버튼 동작 변경
- HTP 전용 캔버스의 색상 제한 변경
- 최근 색상 영구 저장
