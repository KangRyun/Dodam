# 파일 보존·만료·백업·복구 정책 (S15P11B209-622)

> 대상: MinIO 버킷 `dodam` 프리픽스 5종. 담당: Infra(이강륜).
> 설계 근거: `docs/database/저장소-아키텍처.md`(§368) · 운영: `docs/인프라/MinIO백업-복원.md`
> 상태: **A(백업)·B(tts ILM)·C(이 문서) 구성 완료 / D(보존기간 등)는 팀·자문 결정 대기**

이 문서는 **"정책(무엇을 언제까지·어떻게)"** 을 정의한다.
**"실행(삭제 큐 워커·탈퇴 즉시삭제)"** 은 BE `S15P11B209-373` 소관 — 둘은 짝으로 동작한다.

- **백업**: `minio-backup.sh` 가 `tts-cache/` 만 제외하고 전 프리픽스를 야간 백업(14일 보관).
- **자동만료(ILM)**: `infra/minio/lifecycle.json` — 현재 `tts-cache/` 30일 하나. `mc ilm import` 로 멱등 적용.
- **삭제 주체 구분**: ILM(시간 경과) vs BE 373(사건 기반 — 탈퇴·동의철회). **아동 데이터 즉시 삭제는 TTL을 기다리지 않는다**(설계 §5).

| 파일 삭제 실행(373) | BE | 탈퇴·동의철회 이벤트 → 삭제 큐 워커가 MinIO 객체·Mongo 문서 삭제 |

## D — 결정 대기 (팀·심리상담 자문)

1. **images/audio/reports 보존기간(일수)** — 동의 항목·버전과 연동해 확정 필요. 임의 수치 금지.
2. **evidences/ 탈퇴 시 처리** — 법적 보존 vs 삭제권 충돌(설계 §9.1). 보존 시 **비식별화 방식** 포함 결정.
3. **보관정책 변경의 소급 적용** — 정책 단축 시 기존 객체 만료를 당길지(동의 버전 관리 연동, 설계 §9.2).
4. **EBS at-rest 암호화** — OS서 판별 불가 → SSAFY/AWS 콘솔 확인(설계 §8 ⚠️).
5. **파일 열람 감사 로그** — 누가 어떤 아동 그림을 언제 봤나(audit_logs 연동) = 설계상 4차 후보.

> 위 1~3이 정해지면 이 표의 `[결정 대기]` 를 실수치로 채우고, 필요 시 `lifecycle.json` 에 프리픽스 만료 규칙을 추가한다(단, 사건 기반 삭제는 여전히 373).
