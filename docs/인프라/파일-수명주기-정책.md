> 대상: MinIO 버킷 `dodam` 프리픽스 5종. 담당: Infra(이강륜).
> 설계 근거: `docs/database/저장소-아키텍처.md`(§368) · 운영: `docs/인프라/MinIO백업-복원.md`
> 상태: **A(백업)·B(tts ILM)·C(이 문서) 구성 완료 / D(보존기간 등)는 팀·자문 결정 대기**

이 문서는 **"정책(무엇을 언제까지·어떻게)"** 을 정의한다.
**"실행(삭제 큐 워커·탈퇴 즉시삭제)"** 은 BE `S15P11B209-373` 소관 — 둘은 짝으로 동작한다.

- **백업**: `minio-backup.sh` 가 `tts-cache/` 만 제외하고 전 프리픽스를 야간 백업(14일 보관).
- **자동만료(ILM)**: `infra/minio/lifecycle.json` — 현재 `tts-cache/` 30일 하나. `mc ilm import` 로 멱등 적용.
- **삭제 주체 구분**: ILM(시간 경과) vs BE 373(사건 기반 — 탈퇴·동의철회). **아동 데이터 즉시 삭제는 TTL을 기다리지 않는다**(설계 §5).

## ⚠️ 실태 — 위 표는 아직 "계획"이다 (2026-07-28 실측)

위 정책표는 프리픽스 5종을 전제하지만, **구현에 존재하는 프리픽스는 2종뿐**이다.

| 프리픽스 | 설정 | 실제 |
|---|---|---|
| `images/` | `S3_IMAGE_PREFIX` (기본 `images`) | ✅ 동작 중 (71개) |
| `audio/` | `S3_AUDIO_PREFIX` (기본 `audio`) | ✅ 준비됨 — 데이터 0건 |
| `tts-cache/` | **설정 없음** | ❌ **아무것도 들어가지 않는다** |
| `reports/` | 설정 없음 | ❌ 미구현 (`reports.pdf_storage_key` 컬럼만 존재) |
| `evidences/` | 설정 없음 | ❌ 미구현 |

```java
// S3StorageProperties — 프리픽스 필드가 둘뿐이다
@DefaultValue("images") String imagePrefix,
@DefaultValue("audio")  String audioPrefix,
```

### 그래서 지금 일어나는 일

**① ILM 규칙이 헛돌고 있다.** `lifecycle.json` 의 `tts-cache-expire-30d` 는 `Enabled` 지만
대상 객체가 하나도 없다. **"규칙이 존재하는 것"과 "동작하는 것"은 다르다** — 규칙 목록만 보고
"30일 만료가 걸려 있다"고 판단하면 안 된다.

**② TTS 음성이 아동 음성 원본과 같은 곳에 쌓인다.**

```java
QuestionTtsService (TTS 합성)   ─┐
                                 ├─→ AudioStorage → audio/...
VoiceAnswerService (아동 음성)  ─┘
```

`AudioStorage` 인터페이스에 용도를 구분할 인자가 없고(`stage`/`promote`/`read`/`delete`),
구현체는 단일 prefix 만 안다. **설정으로는 분리할 수 없고 BE 코드 변경이 필요하다.**

그 결과:
- TTS 캐시에 **30일 만료가 걸리지 않아 무한 누적**된다
- 재생성 가능한 파생물이 **6시간마다 백업에 통째로 들어간다**
- 백업 용량이 대화량에 비례해 늘어난다

지금은 음성·TTS 데이터가 0건이라 증상이 없지만, 대화 기능이 정상화되면 바로 나타난다.

### 언제 고치나

**S15P11B209-373** 의 범위다 — 그 이슈 본문의 *"`tts-cache/` 프리픽스 정리 정책"* 항목이
이것을 가리킨다. 다만 **음성·TTS가 한 번도 동작한 적이 없어**(대화 메시지 32건 중 VOICE 0건,
`conversation_message_audio_variants` 0행) 프리픽스를 나눠도 **실동작 검증은 불가능**하다.
대화 흐름이 정상화된 뒤에 착수하는 편이 낫다.

## D — 결정 대기 (팀·심리상담 자문)

1. **images/audio/reports 보존기간(일수)** — 동의 항목·버전과 연동해 확정 필요. 임의 수치 금지.
2. **evidences/ 탈퇴 시 처리** — 법적 보존 vs 삭제권 충돌(설계 §9.1). 보존 시 **비식별화 방식** 포함 결정.
3. **보관정책 변경의 소급 적용** — 정책 단축 시 기존 객체 만료를 당길지(동의 버전 관리 연동, 설계 §9.2).
4. **EBS at-rest 암호화** — OS서 판별 불가 → SSAFY/AWS 콘솔 확인(설계 §8 ⚠️).
5. **파일 열람 감사 로그** — 누가 어떤 아동 그림을 언제 봤나(audit_logs 연동) = 설계상 4차 후보.

> 위 1~3이 정해지면 이 표의 `[결정 대기]` 를 실수치로 채우고, 필요 시 `lifecycle.json` 에 프리픽스 만료 규칙을 추가한다(단, 사건 기반 삭제는 여전히 373).
