# 웹 프론트(Next.js) 배포 계획

> Jira: **S15P11B209-383** · 작성 2026-07-23 · 담당 이강륜(INFRA)
> 대상: `frontend/web` (Next.js 16 + React 19 + Tailwind 4, pnpm) — 커뮤니티 웹

## 1. 현황

- 라이브 루트(`https://i15b209.p.ssafy.io/`)는 **임시 페이지**(S15P11B209-302, "산출물이 생기면 교체" 전제).
- `frontend/web`은 커뮤니티 화면 5종(256~260) 구현, **더미 데이터 기반·미배포**.
- 2026-07-23 dev 서버(127.0.0.1:3100) + SSH 터널로 실동작 확인 완료 (`/` → `/community` 리다이렉트 정상).

## 2. 핵심 결정 3가지

### ① 경로 — 루트(`/`)에 걸고 임시 페이지 교체 (basePath 안 씀)

- 임시 페이지가 원래 "산출물 나오면 교체" 전제(302)였음.
- Next 산출물은 정적 자산을 절대경로 `/_next/*`로 참조 → **`/community`만 프록시하면 자산 404**로 화면 깨짐. 루트 장착이면 문제 자체가 없음. FE 코드 수정 0.
- nginx는 **최장 접두사 매칭**: `/api/`·`/ai/`·`/grafana/`·`/jenkins/`·`/download/` 등 기존 라우트가 항상 우선, 웹은 `location /`(나머지 전부)만 받음.

### ② 빌드 — `output: 'standalone'` + 멀티스테이지 Dockerfile

- standalone = 서버 실행에 필요한 파일만 추린 self-contained 번들 → node_modules 통짜 대비 이미지 대폭 축소.
- 스테이지: `deps(pnpm install)` → `build(next build)` → `runner(node:24-alpine, 비루트 유저)` — 백엔드 Dockerfile과 동일한 멀티스테이지 원리.
- FE 변경 필요분: `next.config.ts`에 `output: 'standalone'` 한 줄 (**FE 합의 포인트**).

### ③ 타이밍 — 서빙 편입은 k3s 컷오버(07/28) 이후

- compose에 지금 넣으면 5일 뒤 k3s 매니페스트로 재작업 = 이중작업. **MinIO·Mongo를 "컷오버 후에만"으로 미룬 것과 동일 원칙.**
- 컷오버 전 가능한 준비물: FE 합의, Dockerfile 작성, 로컬 빌드 검증.
- 웹이 아직 더미 데이터라 서빙을 서두를 이유 없음 — 일정상도 자연스러움.

## 3. 단계 분해

| 순서 | 작업 | 담당 | 시점 |
|---|---|---|---|
| 1 | FE 합의: standalone 설정 · 루트 교체 · `NEXT_PUBLIC_API_BASE_URL` 주입 방식 | 강륜↔FE | 지금 가능 |
| 2 | `frontend/web/Dockerfile` 작성 + 로컬 빌드 검증 | 강륜 | 컷오버 전 가능 |
| 3 | k3s 매니페스트 `dodam-web` 추가(내부 3000, 호스트 포트 비노출) + Ingress/nginx 라우팅 + 임시 페이지 제거 | 강륜 | **컷오버 후** |
| 4 | Jenkins web 빌드·배포 스테이지 (`frontend/web` 변경 감지 시만 빌드) | 강륜 | 컷오버 후 |
| 5 | 가드레일 점검: 커뮤니티 격리(CLAUDE 9절), 무인증 공개면 검증 | safety-review | 배포 전 |

## 4. 설계 주의점

- **`NEXT_PUBLIC_*`는 빌드 시점에 번들에 구워지는 값** — 런타임 주입 불가. API URL 변경 = 재빌드 필요. Jenkins에서 **build-arg로 주입**하는 구조로 설계할 것 (백엔드처럼 "재기동하면 반영" 아님).
- dev 서버(`next dev`)는 공개 서빙 금지 — 핫리로드·소스맵·미최적화. 공개는 반드시 `next build` 산출물로.
- 포트: 호스트 3000은 Grafana 점유 — `dodam-web`은 컨테이너 내부 포트만 쓰고 호스트 바인딩 없이 리버스 프록시 경유(다른 서비스와 동일 패턴).
- 이미지 태깅·푸시·배포는 기존 Jenkins 파이프라인 패턴을 따름.

## 5. 가드레일 (CLAUDE.md 9절)

- **커뮤니티 격리**: AI 분석 결과·대화 내용이 커뮤니티 웹에 노출되지 않는 구조인지 배포 전 확인 (BE API 응답 범위 포함).
- 무인증 공개 페이지이므로 개인정보·아동 데이터가 초기 렌더/번들에 포함되지 않는지 검증.
- 179 교훈 재적용: 공개 경로 신설 시 "무엇이 인증 없이 인터넷에 노출되는가"를 항상 먼저 점검.

## 6. FE 합의 포인트 (요청 목록)

1. `next.config.ts`에 `output: 'standalone'` 추가
2. 루트 교체 방식 합의 (임시 페이지 제거 시점)
3. `NEXT_PUBLIC_API_BASE_URL` 등 환경변수 목록 확정 (빌드타임 소성 전제)
4. (별건·앱) release 매니페스트 `INTERNET` 권한 누락 — `android/app/src/main`에 없음, release 빌드 시 네트워크 전멸
5. (별건·앱) 401 응답에 즉시 재시도 루프 관찰됨(6초 8회) — 401은 재시도 대신 로그인 유도로
