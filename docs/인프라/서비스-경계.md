# 서비스 경계 (MSA-lite)

> Jira: `S15P11B209-363` · 작성 2026-08-02 (as-built)
> 함께 볼 것: `docs/인프라/k3s-컷오버.md`(전환) · `docs/database/저장소-아키텍처.md`(데이터) · `docs/api/`(계약)

## 0. 무엇이 "MSA-lite"인가

서비스는 넷으로 나뉘어 있지만(**backend · ai · web · gateway**) 노드는 하나다.
프로세스 경계는 진짜고, **물리 경계는 없다.** 이 문서는 그 경계가 정확히 어디이며
무엇에 기대고 있는지를 적는다 — 나중에 노드를 늘릴 때 **무엇이 먼저 깨지는지** 알기 위해서다.

```
      인터넷
        │  443 (hostPort)
   ┌────▼─────┐
   │ gateway  │  nginx — 유일한 외부 진입점
   └──┬───┬───┘
      │   └────────────┐
 /api/│                │ /  ·  /legal/  ·  /download/
   ┌──▼──────┐    ┌────▼────┐
   │ backend │    │   web   │  Next.js SSR
   └──┬──┬───┘    └─────────┘
      │  └──────────────┐
      │ MySQL·Mongo·    │ 내부 HTTP (X-Internal-Token)
      │ Redis·MinIO     │
   ┌──▼──────────┐  ┌───▼───┐
   │  데이터 계층 │  │  ai   │  FastAPI + YOLO
   └─────────────┘  └───┬───┘
                        │ 외부 (GMS: LLM·STT·TTS)
```

## 1. 외부 경계 — gateway 가 전부다

**외부에 열린 포트는 gateway 의 80/443 뿐이다.** 나머지 서비스는 전부 ClusterIP 라
클러스터 밖에서 직접 닿을 수 없다.

| 경로 | 대상 | 비고 |
|---|---|---|
| `/` | `web:3000` | 랜딩·커뮤니티(Next SSR) |
| `/api/` | `backend:8080` | 공개 API. 인증은 backend 가 한다 |
| `/ai/` | `ai:8000` | **접두 `/ai/` 를 떼고** 전달(`proxy_pass` 끝의 `/`) |
| `/legal/` · `/download/` | 정적 | **전용 location 필수** — §1.1 |
| `/grafana/` · `/jenkins/` | 각 서비스 | 변수 upstream(없어도 게이트웨이가 뜨도록) |
| `/internal/` · `/ai/internal/` · `/ai/metrics` | — | **404 로 차단** |

### 1.1 두 가지 함정 (실제로 겪은 것)

**① 내부 경로 차단은 `/ai/` 접두 제거 때문에 별도 블록이 필요하다.**
`/ai/` 가 접두를 떼고 전달하므로, 차단 블록이 없으면 외부에서 `/ai/internal/...` 이
ai 컨테이너의 `/internal/...` 에 **그대로 도달**한다. nginx 최장 접두 매칭이라
`/ai/internal/`·`/ai/metrics` 블록이 `/ai/` 보다 먼저 잡혀 404 를 낸다.

**② `location /` 을 바꾸면 딸려오던 정적 경로가 사라진다.**
383 이전에는 catch-all `location /` 이 정적 root 를 서빙해서 `/legal/`·`/download/` 가
자동으로 딸려왔다. `/` 를 web 프록시로 바꾸는 순간 **개인정보처리방침·이용약관이 통째로 404** 가
된다 — 스토어 심사에 제출한 URL 이다. 그래서 전용 location 을 명시적으로 둔다.

> 교훈: 라우팅을 바꿀 때는 **이미 외부에 공표한 URL 이 있는지** 먼저 확인한다.

## 2. backend ↔ ai 경계

### 계약

| 항목 | 값 |
|---|---|
| 방향 | **backend → ai 단방향**. ai 는 backend 를 부르지 않는다(예외: §2.1) |
| 인증 | 헤더 `X-Internal-Token` (정본 명세는 `X-Internal-Api-Key` — **양쪽 다 수신**) |
| 시크릿 | `AI_INTERNAL_TOKEN` — backend·ai 가 같은 값을 공유 |
| 주요 엔드포인트 | `/internal/v1/analyses`(그림 분석) · `/internal/v1/observations`(관찰 리포트) · `/internal/ai/v1/speech/stt` · `/internal/v1/health` |
| 계약 정본 | `docs/ai/*-contract.md` — **AI·BE 양쪽을 동시에 고쳐야 한다** |

⚠️ **토큰 미설정 시 ai 는 기동 자체를 거부한다**(fail-closed, `main.py` lifespan).
"비어 있으면 검사 생략" 폴백은 nginx 접두 제거와 결합해 내부 계약이 무인증으로
인터넷에 노출되는 경로였기 때문에 제거했다(C-183-1).

⚠️ **헤더 이름을 한쪽만 바꾸면 조용히 망가진다.** BE 는 401 을 `Type.OTHER` 로 분류해
**폴백 템플릿으로 대체**하므로, 화면은 멀쩡하고 품질만 떨어진다. 두 헤더를 함께 받는 이유다.

### 2.1 단 하나의 역방향 — AI 이미지 접근

ai 는 아동 그림을 읽어야 하는데 **MinIO 자격증명을 주지 않는다.** 대신 backend 가
1회용 토큰을 발급하고(`/internal/v1/ai-images/{token}`, TTL 60초), ai 는 그 URL 로만 받는다.

> 이 설계 때문에 `ai-ro` MinIO 계정은 **아무도 쓰지 않는 유휴 자격증명**이 되어 회수했다(673).
> 저장소 자격증명을 나눠주는 대신 **짧게 사는 접근권을 발급**하는 것이 이 경계의 원칙이다.

## 3. 데이터 경계

| 저장소 | 소유자 | 다른 서비스의 접근 |
|---|---|---|
| MySQL | backend 전용 | 없음 |
| MongoDB | backend 전용 (스트로크 배치) | 없음 |
| Redis | backend 전용 (토큰·캐시) | 없음 |
| MinIO | backend 전용 | ai 는 §2.1 토큰 경유만 |
| ai-models PVC | ai (읽기 전용) | 없음 |

**원칙: 저장소를 공유하지 않는다.** 서비스 간 데이터는 반드시 HTTP 계약을 지난다.
지금은 노드가 하나라 물리적으로는 다 같은 디스크지만, **코드에 그 전제를 넣지 않는다.**

## 4. 단일 노드 전제 — 무엇이 먼저 깨지는가

**모든 PVC 가 `ReadWriteOnce`(RWO)다.** RWO 는 *한 노드*에만 붙는다.

| 항목 | 지금 (단일 노드) | 노드가 늘면 |
|---|---|---|
| `backend-storage` PVC | backend replicas 2 가 **같은 노드**라 공유됨 | **깨진다** — 다른 노드의 파드가 마운트 불가 |
| MySQL·Mongo·MinIO·Redis | StatefulSet 각 1개 | 스케줄 노드에 고정(nodeAffinity 필요) |
| gateway `hostPort` 80/443 | 노드가 하나라 곧 공개 IP | 노드마다 IP 가 달라짐 → LB 필요 |
| 로컬 레지스트리 `127.0.0.1:5000` | 노드 내부 주소 | **깨진다** — 다른 노드가 못 당김 |

### 전환 경로 (노드를 늘릴 때)

1. **파일 저장은 이미 준비돼 있다** — `STORAGE_MODE=s3` 로 MinIO 를 쓰므로 `backend-storage`
   PVC 는 폴백 경로일 뿐이다. RWO 제약이 실질 장애가 되지 않는다.
2. **레지스트리를 노드에서 접근 가능한 주소로** 바꾼다(`127.0.0.1:5000` → 클러스터 서비스 또는 외부 레지스트리).
3. **gateway 를 hostPort → LoadBalancer/Ingress** 로 바꾼다.
4. StatefulSet 에 `nodeAffinity` 를 명시해 데이터가 따라다니지 않게 고정한다.
5. MinIO 는 단일 드라이브라 erasure coding 이 없다 — 다중 노드로 갈 때 재구성 검토.

> **지금 하지 않는 이유**: 노드가 하나인 동안 위 작업은 전부 "미래를 위한 복잡도"다.
> 대신 **어디가 부러지는지 적어 둔다** — 그게 이 문서의 목적이다.

## 5. 배포 경계 — Jenkins 가 할 수 있는 것/없는 것

| 할 수 있다 | 할 수 없다 |
|---|---|
| 이미지 빌드·푸시 | 워크로드 **생성**(Deployment·Service 신설) |
| `kubectl set image` (SHA 태그) | ConfigMap·Secret 반영 |
| `rollout status` 확인 | 리소스(limits) 변경 |

**최소권한의 대가는 "한 번은 사람이 해야 함"이다.** 새 서비스를 추가하거나 설정을
바꾸면 사람이 `apply` 해야 한다. 이걸 모르면 "머지했는데 반영이 안 된다"로 나타난다(751).

⚠️ **`kubectl apply -k overlays/prod` 를 그대로 실행하지 말 것.** overlay 는 이미지 태그를
`:prod` 로 고정하는데 클러스터는 Jenkins 가 넣은 SHA 로 돈다 → 4개 서비스가 통째로 되돌아간다.
안전 절차는 `S15P11B209-609` 코멘트 참조(렌더 → 태그를 현재 SHA 로 치환 → `kubectl diff` 로
이미지 변경 0건 확인 → apply).

## 7. 알려진 열린 항목

- **다중 노드 전환 계획 없음** — §4 는 "깨지는 지점" 목록이지 실행 계획이 아니다.
- **로그 집계 스택 없음** — Prometheus 지표만 있고 로그는 파드 stdout 에 머문다(611 보류 사유).
- **파일 열람 감사 로그 미구현** — 누가 어떤 아동 그림을 언제 봤는지 남지 않는다.
- **at-rest 암호화 미확인** — EBS 볼륨 암호화 여부는 OS 안에서 판별 불가.
