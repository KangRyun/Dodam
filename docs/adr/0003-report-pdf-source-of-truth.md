# ADR-0003: 리포트 PDF 정본은 서버가 생성한다

> Jira: `S15P11B209-965` (본 문서)
> 상태: **채택(Accepted)** — 2026-08-06
> 관련: 956(앱 캡처 PDF) · 957(서버 PDFBox 서식) · 964(섹션 단위 페이지 분할) · 966(자산 조회 경계) · 967(openhtmltopdf 검증) · 968(템플릿 전환) · 969(앱 전환)

---

## 컨텍스트

관찰 리포트 PDF 레이아웃이 **두 곳**에 생겼다.

1. **앱** — 리포트 화면을 섹션마다 캡처해 A4 로 배치한다(956·964). 화면과 100% 같고 그림·마스코트·감정 칩이 그대로 들어간다. 대신 이미지라 글자를 선택·검색할 수 없고, 문서보다 "긴 모바일 화면"처럼 읽힌다.
2. **서버** — 리포트 DTO 를 PDFBox 로 그린다(957). 글자는 선명하지만 좌표를 손으로 계산하고, 그림을 싣지 못한다(렌더러에 저장소 의존이 없음).

두 개를 함께 유지하면 갈라지는 것이 디자인만이 아니다. **문구·섹션 순서·페이지 분할·그림 포함 여부**가 각각 달라지고, 한쪽을 고칠 때 다른 쪽을 같이 고쳐야 한다. 보호자가 앱에서 저장한 파일과 서버가 보관한 파일이 다르면 어느 쪽이 리포트인지 말할 수 없다.

클라이언트는 이미 둘이다 — Flutter 앱(`frontend/mobile`)과 Next.js 웹(`frontend/web`). 웹은 아직 리포트 PDF 를 내려받지 않지만, 클라이언트마다 문서를 만들면 세 번째 구현이 생긴다.

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| **앱 전용 `pdf`(pw) 문서 레이아웃** | 결과물은 좋다(선명한 글자, 그림·이모지 자유). 그러나 서버 PDF 생성이 **이미 있는 상태**라 문서 레이아웃이 둘로 남는다. 웹에서 내려줄 때 또 만들어야 하고, 리포트 생성 책임이 앱과 서버로 쪼개진다 |
| **앱 캡처 유지 + A4 페이지 전용 위젯** | 화면 위젯을 재사용해 빠르게 문서다워진다. 하지만 결과물이 계속 이미지라 글자 선택·검색이 안 되고 파일이 크다. "모바일 캡처처럼 보인다"는 근본 원인이 그대로 남는다 |
| **서버 PDFBox 좌표 배치 계속 개선** | 정본은 하나가 되지만, 표지·요약 레이아웃과 카드 단위 페이지 분할을 좌표 계산으로 매번 맞춰야 한다. 디자인 수정 비용이 계속 높다 |
| **Chromium headless(HTML→PDF)** | CSS 는 완전하지만 런타임 이미지가 `eclipse-temurin:21-jre-jammy` 비루트 실행이다. 브라우저를 넣으면 이미지가 수백 MB 늘고 메모리·보안 표면이 커진다 |

## 결정

**리포트 PDF 정본은 서버가 생성한다.**

- 렌더링은 **openhtmltopdf 기반 PDF 전용 HTML/CSS 템플릿**으로 한다(967 검증 후 968 에서 전환). 순수 Java 라 런타임 이미지에 브라우저를 넣지 않아도 되고, `page-break-inside: avoid` 로 카드 단위 페이지 분할을 CSS 로 표현할 수 있다.
- **클라이언트는 PDF 문서 레이아웃을 관리하지 않는다.** 앱과 웹은 서버가 만든 같은 파일을 내려받아 저장·공유·인쇄만 한다.
- 앱의 캡처 기반 생성은 968 이 끝난 뒤 제거한다(969). 그 전까지는 보호자가 당장 쓸 파일이 필요하므로 남겨 두되, **여기에 문서 디자인을 더하지 않는다.**

## 따르는 제약

- openhtmltopdf 는 브라우저가 아니다. **flex·grid 를 쓰지 않고** table·block 기반으로 템플릿을 짠다.
- 감정 표시는 컬러 이모지 대신 **PNG 아이콘**을 쓴다. 앱의 `assets/characters/emotions/*.png` 와 같은 자산을 서버 리소스로 공유한다. SVG(Batik)는 슬림 JRE 이미지에서 fontconfig·freetype 부재로 깨질 위험이 있어 피한다.
- 그림 바이트는 **저장소 경계로 내부에서 읽는다**(966). 서버가 자기 JWT 인증 URL 을 HTTP 로 다시 부르지 않는다.
- 담는 데이터·섹션 순서는 계약(`S15P11B209-875` §11)을 그대로 지킨다. 화면엔 있고 PDF엔 없는 데이터를 만들지 않는다.

## 결과

- 앱·웹이 같은 파일을 받는다. 디자인 수정은 서버 템플릿 한 곳만 고친다.
- 글자를 선택·검색할 수 있고 확대해도 선명하다.
- 앱에서 PDF 생성 코드와 `pdf` 패키지 의존성이 사라진다.
- 전환 시 **지금보다 나빠지지 않아야 한다** — 마스코트·그림 갤러리·HTP 3장·감정 칩·해석 카드가 새 템플릿에도 들어가야 한다(969 완료 조건).
